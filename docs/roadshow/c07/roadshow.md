# TradeQuote 路演内容｜约4分钟，8页

受众：项目评审及潜在业务使用者。中文主讲；产品名TradeQuote。视觉沿用浅色、暖橙和清晰单据，避免技术框架徽章、营销空话、假客户证言。“采集资料待审核；询盘为编写案例”的提示放在案例页/证据页的可见角落，不能伪装成真实成交。

## 1｜把一封询盘，变成一份有依据的报价（20秒）

画面：一封客户邮件 → 一份报价单；下方三个词“可核对 / 可修改 / 可回复”。

讲：业务员收到询盘后，需要查商品、核数量和价格、补充条款，还要把变化解释给客户。TradeQuote把这些工作放在同一个单据工作台里。

## 2｜客户只改了数量，业务员却要重新核一遍（25秒）

画面：300→500；商品资料、阶梯价、付款交期、旧版本和回复散在周围。

讲：困难不仅是计算。数量变化会命中不同价格，旧报价要保留，付款与交期可能还没确认。我们围绕一份单据把这些动作连起来。

## 3｜从业务目标开始（35秒）

画面：工作台实际操作/截图，显示用户询盘和助手追问。提示“采集资料待审核；询盘为编写案例”。

讲：以服装采购为例。客户要300件素色T恤。业务员直接贴入询盘；系统查询已发布商品资料，并向业务员补问付款和交期。这里展示的是编写的询盘案例，商品沿用已有采集资料，尚未完成业务审核。

## 4｜金额有工具计算，单据有资料依据（35秒）

画面：300piece × 39.21CNY = 11763.00CNY；来源版本入口；付款与交期标为拟议条件。用实际保存单据替换概念示意。

讲：补齐需求后，商品金额由确定性业务工具计算并保存为V1。运税费未知就保留未知，不能用零凑出完整总价。资料依据和规则覆盖可以在工作台核对。

## 5｜改成500件，原版还在（40秒）

画面：V1/V2对照。数量300→500，单价39.21→37.21，商品合计11763.00→18605.00，合计增加6842.00。

讲：继续说“数量改为500，比较变化”。系统按新的阶梯价核算、保存新版本，并展示变化。这里单价降低了，但因为多买了200件，商品合计增加6842元。原来的报价不会被覆盖。

## 6｜业务员最后拿到什么（30秒）

画面：当前报价 + 客户回复正文 + 内部核对依据三个清晰区域；可复制正文。

讲：最终留下的是保存的报价版本，以及可以复制、人工核对后使用的客户回复。内部检查ID和来源哈希不混进客户正文。待确认事项仍然可见；复制不代表审批或发送。

## 7｜每个入口只承担自己的工作（30秒）

画面：四个菜单。单据工作台=日常处理；资料与报价=导入发布和历史查询；模型设置=连接；工作区设置=业务默认配置。查询试算直接在工作台使用。

讲：资料维护退到后台，日常处理回到工作台。查资料、算金额、保存和恢复复用同一套业务服务；业务员不用在长页面里按顺序寻找多个按钮。

## 8｜下一步，用真实业务资料验收（25秒）

画面：已实现与待验证两列，强调“从真实询盘验证到可用回复”。

讲：当前我们可以验证工具执行、版本保存、取消恢复和可复制草稿。还需要补齐服装原始快照，复核资料有效期、商业条款和规则；正式审批、外发及PDF仍未完成。下一步是让真实业务员带一份资料完成同样的闭环。
