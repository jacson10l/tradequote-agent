# M0 技术验证记录与复用选型

本轮完成 T01 的两个候选抽取实验，以及 T02 的本机 SDK/runtime 复用可行性实验。**没有完成整个 M0，也没有开始 Electron 产品开发。** 2026-10-21（Asia/Shanghai）的测试输出含 UTC 时间戳，因此机器记录日期为 2026-10-20。

## 本轮选型决定

| 对象 | 决定 | 实际依据 |
|---|---|---|
| Solivio 整体 | 不 Fork；参考工作流，按本项目契约实现 | Next/Postgres/pg-boss/SDK runtime 与本地 Electron 边界不同；两个独立抽取候选也需要改写关键语义 |
| Solivio CSV 与映射 | 不复制到生产；采用 `csv-parse 7.0.3`，自建可配置映射/decimal 解析 | 3 个兼容样例、分隔符/损坏输入/固定 schema/locale 的差异已经复现 |
| Solivio 金额 helper | 不复制到生产；采用 `decimal.js 10.6.0` 与自有定价领域 | 实际得到 `0.1 + 0.2 = 0.30000000000000004`；上游 helper 不负责本项目输入和规则校验 |
| Harness | **有条件采用官方 SDK/runtime＋自有业务 profile**；不 Fork 内核 | 真 runtime 已完成业务工具链、越权/参数拦截、会话恢复、取消与进程回收 |
| DeepSeek 模型 | 保持优先路线；真实模型型号与能力尚未锁定 | 未配置 Key/模型；实验使用本地模拟 Messages API，模型名仅为 runtime 路由 fixture |

这是复用方式的选型决定，不是宣布最终运行版本已经冻结。Harness 的打包和真实模型关卡未完成；若其必需能力不通过，才按既定方案切换最小受控执行器。暂时没有证据要求现在重写 Harness 已提供的执行与恢复机制。

## 实验环境与可复现证据

- 实测 macOS 26.4（25E246）、arm64、Darwin 25.4.0；Node 22.22.0、pnpm 10.13.1。
- Harness client/runtime/tools 固定 `0.2.1-rc.2`；tsx `4.23.15`；其余版本和 integrity 固定在独立锁文件。
- 安装命令：`pnpm --dir experiments/m0-reuse install --frozen-lockfile --ignore-scripts`。
- 复验命令：`pnpm --dir experiments/m0-reuse test`，两条子命令均退出 0；[机器摘要](../../experiments/m0-reuse/evidence/summary.json)包含环境、准确版本、命令、hash。
- 使用源文件原样副本；每次复验校验 SHA-256。只对合成 fixture 操作；未读取真实密钥值或客户数据。
- Solivio 上游 Node ≥24.15.0/Yarn 约束没有在本轮整套构建中验证；抽取函数通过不代表原工程能用当前 Node 构建。
- Harness npm 发布包没有可查询的 `gitHead`，静态 commit 与实际发布版本分别记在 [UPSTREAM](../../UPSTREAM.md)。

## T01：Solivio 两个候选的依赖与样例

| 候选 | 直接依赖 | 传递依赖与抽取方式 | 迁移决定 |
|---|---|---|---|
| `productParser.ts` | `import type ProductInput from @solivio/sdk`；JS 标准库 | 类型导入运行时擦除，因此可直接由 tsx 运行；若保留类型则须迁移固定字段 DTO，不能把整个 SDK 引进领域层 | 不迁入生产；保留本轮刻画样例 |
| `offerTotals.ts` | 无 import | 无传递依赖，原样抽取执行 | 不迁入生产；用 Decimal 和显式输入/规则校验重写 |

完整副本/许可/来源 hash 见 [Solivio provenance](../../experiments/m0-reuse/vendor/solivio/provenance.json)。没有做上游全量 TypeScript 构建。

**11/11 行为刻画测试通过，其中 8 个是“确认差异存在”的测试，不是 11 个产品验收通过。**

| 样例 | 实际结果 | 对本项目的含义 |
|---|---|---|
| BOM＋分号＋中文属性、引号/转义/多行、Tab | 与明确指定分隔符的 csv-parse 一致，3 项通过 | 基本 CSV 行为可借鉴 |
| 表头 `"sku;a;b;c",name` | 自动猜成分号；csv-parse 指定逗号可正确读 | 导入先预览并确认分隔符，不用字符计数作为最终判断 |
| 未闭合引号 | 上游接受；csv-parse 抛 `CSV_QUOTE_NOT_CLOSED` | 损坏文件必须有明确失败/修正路径 |
| 数据行多一列 | 上游忽略额外单元格；csv-parse 抛列数错误 | 不静默丢弃数据 |
| 缺少 description/gross/VAT | 映射检查能返回缺列；直接 extraction 返回空 records/errors | 上游契约与本项目不同；不是其所有调用方均会静默失败 |
| 中文列名 | 默认别名无法映射 | 映射 UI 和跨品类字段 schema 自建 |
| 价格字符串 `1.234` | 按上游欧洲格式策略变成 `1234` | 必须显式选择数字 locale；不自动猜三位小数/千分位 |
| 两项 `0.1`、`0.2` 汇总 | Number 得到 `0.30000000000000004`；Decimal 得到 `0.30` | 采用十进制字符串全链路 |
| 负数量/150% 折扣 | helper 返回负总价，无校验 | 本项目规则校验属于自有领域服务；不据此声称整个上游没有校验 |

csv-parse 也不解决所有导入问题：重复表头、空表头、行级来源、字段确认、单位/币种与数值 locale 仍由 A 在 T21 实现。两种定价/舍入/trace 属于 B 的 T30，本轮 Decimal 对照只证明十进制能力。

PDF、完整 UI 和 knowledge-base 没有做动态抽取实验；保留原 T04/后续任务，不把静态阅读写成运行成功。

## T02：实际运行的 Harness 链路

```text
探针宿主 → 官方 SDK → 独立 dsh runtime 子进程
                     → 自有 profile，只挂三个业务工具
                     → 127.0.0.1 模拟模型 Messages/SSE
                     → 工具桥接 → 宿主内存业务 fixture
```

模型响应是预先编排的合成数据；执行循环、工具注册/校验、stdio 传输、会话日志与恢复来自真正安装的 Harness。业务计算由宿主 Decimal 执行，最终草稿保存在宿主内存，runtime 不拥有报价状态。

| 实测项 | 结果 | 边界 |
|---|---|---|
| 同版本 SDK/runtime 握手 | 通过；本机数百毫秒，精确值见机器记录 | 单次本机观测，不是性能基准 |
| `search_catalog → calculate_quote → create_quote_revision` | 通过；3×0.10 = `0.30`，产生一个 draft；56 个 session events | 三个工具是接入探针，不是完成的业务应用 |
| 实际发给模型的工具列表 | 每次请求严格等于三个业务工具 | 默认 shell/read_image/working_directory 工具和 MCP 被禁用 |
| 模型调用未提供的 `bash` | 工具错误，未进入宿主业务服务 | 工具名单/guard 是能力限制，不是 OS 级沙箱 |
| quantity 传 number；伪造 workspaceId | 两项均被拒绝；前三项恶意/错误调用共得到 3 个工具错误 | schema 类型校验由 Harness；未知字段由自有桥接拒绝 |
| 重复 create | 同一宿主操作幂等键返回相同 revision，共 1 个版本 | 宿主 fixture 的幂等语义；不是 Harness 自动实现业务幂等 |
| 正常退出＋新进程恢复会话 | 通过；重新尝试写入仍只有 1 个版本 | 同一 dshHome JSONL；宿主内存持续存活 |
| 模型响应挂起时关闭 runtime | 通过；pending run 以 `TransportClosedError` 结束，约 21ms；进程 PID 已消失 | 取消发生在已有版本提交后、下一轮模型请求期间；不代表提交竞态已测 |
| 取消后重建进程/恢复 | 通过；同一草稿不重复写入 | 宿主崩溃恢复待真实数据库验证 |
| 恢复不存在 session | 被拒绝 | 没有静默创建替代会话 |
| `session/cancel` 探测 | 返回 unknown method，JSON-RPC `-32603` | SDK 无此接口；不是 run 级 cancel API |
| 最后关闭进程 | 通过，无该实验拥有的 runtime 残留 | 用 OS PID 查询核对；没有依赖 SDK 私有属性 |

最新精确结果见 [harness.json](../../experiments/m0-reuse/evidence/harness.json)。11 个检查项全部符合预期，其中一项专门确认“没有单会话取消接口”。首次该探针误预期未知方法应返回 `-32601`，实际由 server handler 抛错映射为 `-32603`；核查上游 dispatcher 后修正断言并重跑，不把它记录为功能故障。

## Harness 接入必须遵守的限制

1. 一个活动 AgentRun 独占一个 runtime 进程。取消关闭进程；顺序执行可在同一进程复用会话。不能多个活动 run 共用进程后假装能独立取消。
2. SDK `requestTimeoutMs` 是停止等待，不保证服务端停止执行。应用超时路径必须关闭/回收运行时，再把 run 标成 interrupted/failed，不能仅 reject UI Promise。
3. `defineTool` 参数根对象默认开放，额外字段可进入 execute。本实验桥接主动拒绝；生产使用严格 Zod DTO，工作区/actor/权限/幂等上下文仅由宿主注入。
4. 官方 provider 在此版本走 Messages API（`/v1/messages`），不是 Chat Completions 接口。SDK 选择 provider/model 不等于可直接注入任意 `ModelProvider` 实例；新供应商需可信 provider 插件或另一个 AgentRuntime 实现，禁止接受用户任意插件路径。
5. 最终文本不当作业务提交证据。工具返回结构化值、宿主提交事件、revisionId 才能刷新单据；自由文本 JSON 还需本项目 schema 校验与修正流程。
6. profile 禁用不等于裁剪安装包。首次依赖安装加入 565 个包，磁盘约 541MiB；修正/增补依赖后本地 node_modules 约 557MiB，含实验工具/可选包/旧解析目录，**不是 Electron 安装包大小**。分发体积和未使用包裁剪需独立测量。
7. 初次解析 `@opentelemetry/api 1.10.0` 不满足 OTel SDK `<1.10.0`；已在实验固定为 `1.9.1`，处于所有已观察约束交集，重新安装无此 peer 警告并复验通过。当前仍有 `node-domexception@1.0.0` 弃用提示；本 profile 未启用遥测，没有声称遥测能力已测。
8. 本轮禁用 lifecycle scripts 仍可启动所用 profile；不据此假定 Electron ASAR、Node 可执行文件路径、平台原生包和签名均可用。
