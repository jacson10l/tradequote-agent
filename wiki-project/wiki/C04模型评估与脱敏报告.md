# C04模型评估与脱敏报告

## 当前范围

从 C02c 0ccd72f 的真实公开服务建立独立评估入口，不修改业务 DTO、迁移、Provider、运行调度或桌面 IPC。入口 `pnpm eval:model --mode fixture` 使用 Electron 的 Node ABI，运行真实 DeepSeekProvider 响应解析、AgentRunCoordinator、受控工具循环、隔离 SQLite、真实商品与规则发布/查询、确定性金额和同事务草稿保存。替身仅生成模型 HTTP 响应；没有用替身代替业务成功结果。

所有输入是合成商品、合成买方和明确不代表实际平台政策的合成规则。每个用例创建临时工作区并在 finally 关闭/移除；不访问正在使用的 userData、凭据文件、真实客户数据库或环境 Key。固定依赖沿用 Node22.22.0/pnpm10.13.1/Electron44.9.2，没有新增依赖或改锁文件。入口默认报告 `.runtime/c04-fixture.json` 和 `.md`，`--output` 是报告前缀；不传 mode、重复参数、Key 或端点参数都拒绝。

fixture 是预先编排的响应，不证明模型真的理解中文、英语或德语；它证明样本、语义断言和生产业务链可执行，且不能将错误接受为保存成功。真实供应商、人工模型语义评价、安装和 Windows 均未验收。任务见 [[C04-评估样本与脱敏报告]]，与 [[C02c多步报价工具闭环]] 的既有业务范围保持一致。

## fixture和真实DeepSeek

`--mode fixture` 使用内存 HTTP Response 替身，固定 synthetic model，报告 providerValidation=fixture_only、realRequests=0。首次实际48点通过，186次替身请求；不同调用次数或错误码会导致相应检查失败。单元测试禁止全局 fetch，证明 fixture 不访问外部网络。

`pnpm eval:model --mode deepseek` 在本切片 CLI 不接受凭据，生成 status=not_run、providerValidation=not_run、model=null、48行未运行、0请求并退出2；这不是测试失败或供应商通过。没有自动从环境、设置或文件获取 Key，也不提示用户把 Key 粘到聊天/命令参数。合法 fixture通过退出0，观测不符合期望退出1，未运行退出2，参数非法退出1。

内部 `evaluateC04` 留有宿主显式传入合法 ModelCredentials 的真实模式：仅使用固定生产 DeepSeekProvider/官方端点，没有可传入的假 Provider 或自定义端点。真实模式仅运行语义/澄清/规则用例，17个故障注入标 fixture_only/未运行，不对供应商制造假限流。该路径尚未通过正式模型设置 UI 接线，也未实际调用；后续经明确授权由宿主使用本次用户配置的模型凭据，在隔离工作区运行并保留实际结果，不因 API 或类型存在而称真实验收完成。原样本/预期不随模型输出修改，失败应保留而非调期望凑通过。

## 脱敏报告

报告是 strict 白名单投影：固定 caseId/分组/语言、状态/枚举原因、公开错误码及期望码、固定检查名/布尔值、耗时、调用次数、suite版本、caseSetHash、日期及合法模型ID。JSON 与 Markdown 都从同一已校验报告生成。没有 prompt、模型回答、summary、询盘正文、认证头、Key、错误栈、原件、工作区路径或报价完整快照；不依靠正则删几个敏感词。模型ID与已知Key相撞时省略模型ID。报告不能少行、重复行、改变样本标签、把无检查写成 passed 或伪造 fixture 的真实请求计数。

caseSetHash 固定合成输入、计划和期望错误码；源码实际 SHA-256 另由本机验证记录固定。当前 adapter 不暴露 token/usage/价格，tokens/cost 明确 null，不推算费用。报告中 realRequests 是发起真实 fetch 的次数而非供应商成功计费数。fixture 响应正文中放置合成保密标记，单元断言这些内容及合成Key不进入 JSON/Markdown。
