# 测试与交付

本页是未来 MVP 的验收标准，不是当前测试报告。MVP 完成需要业务正确、模型真实调用、桌面安装和异常恢复同时具备证据；当前仅交付开发文档。

## 测试分层与归属

| 层 | 验证对象 | Owner | 通过标准 |
|---|---|---|---|
| 领域单元 | Decimal、档位、换算、费用分摊、状态/规则、差异 | B | 明确输入与独立计算的期望值全部匹配 |
| 数据/契约 | 四类格式、Zod、SQLite 事务、幂等、迁移、引用 | A＋B | 真 SQLite 与样本文件通过；回滚无半成品 |
| Agent adapter | 工具白名单、结构失败、限流、取消、恢复 | C | 故障可观察；失败不伪装成无结果；不重复提交 |
| Renderer 交互 | 映射、单据编辑、风险定位、差异、审批门禁 | 对应 feature owner | 用户行为可完成，加载/失败/空态可理解 |
| Electron 集成 | 实际 IPC、后台崩溃、凭据、文件路径、PDF | C | 真实窗口和后台；浏览器 mock 不能替代 |
| 模型评估 | 跨品类理解、澄清、来源、多语言、两轮变化 | 全体 | 有真实 run/tool/version 记录；人工评分 |
| 安装验收 | macOS/Windows 安装、运行、重启、升级 | C/A | 两个系统分别留下实际结果与产物 hash |

## 确定性边界样例

| 样例 | 独立期望 |
|---|---|
| 阶梯 `[1,100)` 单价 10，`[100,∞)` 单价 9 | 数量 99 → 990；100 → 900；减量必须重新选档 |
| CNY 72 成本，7.2 CNY/USD，20% 毛利，1500 件 | 成本 USD 10/件；报价 USD 12.50/件；总额 USD 18,750 |
| 数量 3，单价 USD 0.335，币种 2 位，HALF_UP | 单价策略允许 3 位时行金额 1.01；不先把单价舍成 0.34 |
| 两行折扣分摊与余数 | 分摊结果总和严格等于整单折扣，固定 lineId 顺序使重跑一致 |
| 采购与销售币种不同、无汇率 | 可保存不完整草稿；总额不显示为完整，不能批准 |
| kg → 件无产品转换依据 | 返回缺项；不能默认 1:1 |
| 0 成本与缺失成本 | 前者是明确数值；后者不能代入 0 |
| margin=1、负数量、NaN、溢出精度 | schema/领域拒绝，有字段定位 |
| 同幂等键同 payload 连续提交 | 同一 revisionId，不产生重复任务 |
| 同键不同 payload | IDEMPOTENCY_CONFLICT，不执行第二次 |
| baseVersion 落后 | REVISION_CONFLICT，返回当前版本，旧修改不落库 |
| 批准后改数量/重新生成译文 | 新版本/新产出不可借旧审批正式导出 |
| PDF 失败或模型断线 | 原 revision 与检查保留，可单独重做失败阶段 |
| 引用源过期/冲突 | 关键适用检查 pending/block，不能无条件通过 |
| 未发布导入内容 | 检索不到可用于正式承诺的事实 |
| 库迁移中断 | 旧库/备份可恢复，不损坏原件与版本引用 |

金额期望由独立手算或基准文件提供，不以被测函数生成自己的预期值。

## 模型评估集

初始准备 10 个开发样例＋20 个保留样例，总计 30 个。分布建议：完整与缺项询盘 6、数量/费用/币种 6、规格/资料规则冲突 4、交易条款缺失 4、两轮修改与多语言一致性 4、超时/重复/冲突/来源失效 6。数据在三个差异化品类间分布。

每例记录输入文件 hash、来源状态、预期关键事实、允许的候选、必须澄清项、禁止承诺、预期规则结果和可接受语言表现。开发者可用合成数据，必须标记；保留集冻结后不拿来调 prompt，通过失败分析修改后需建立新的保留回归样例。

人工评分用 0/1/2：0 错误或不可用，1 可修正，2 可直接审核。维度为事实一致、来源支持、术语准确、语言清楚、下一步可执行。验收目标：事实/金额/来源无 0 分；全部关键不确定项可见；至少 90% 的样例各维度达到 2 分，其余已明确人工修正并有回归记录。该阈值为项目拟定目标，不是已测指标。

英语、德语验证业务表达；额外用日文等 CJK 与阿拉伯文等 RTL 检查版式与字形。其他目标语言仍可生成，但仅把实测通过的组合列入验证矩阵。未配置字体或模型无法完成时明确返回问题，不导出缺字且声称成功的 PDF。

## 跨品类主场景

1. 服装：件数档位＋材料属性；改变数量和包装引起价格与待确认任务变化。
2. 板材：面积单位＋厚度/规格；尺寸或单位信息不足时追问，不能用件价套平方米。
3. 紧固件：重量或包装换算＋材质等级；价目表过期或包装转换缺依据时阻断正式审核。

每类完成 V1→V2→V3；第二类至少用成本核价，另一类用销售价目表。无论品类，领域计算代码不出现 `if category === "tshirt"` 之类分支。

两个输出场景：RFQ 回答选品/条件/澄清；正式邮件包括条款、有效期、附件和下一步。对外正文不泄露采购成本、毛利、内部备注和模型运行信息。

## 双平台安装矩阵

M0 选定实际目标 OS/CPU 并记录。初始建议 macOS arm64、Windows x64；若演示机器为其他架构，以实际目标补齐并测试，不把未测试架构算作已支持。

每个平台都完成：

- 干净用户环境安装、首次启动，无 Node、数据库或字体下载前置要求。
- 非 ASCII 用户目录、带空格文件名、文件不可读/目录不可写。
- 四类输入、三品类主流程、草稿与正式 PDF、多语言字体、长表格跨页。
- 保存与重启回读，模型限流/网络断开、应用退出、后台进程异常。
- 备份→新工作区恢复，旧 schema 升级，演示数据重置隔离。
- 安装包真实运行与签名状态记录；CI 打包成功不代替人工安装。

代码签名/公证证书由发布渠道决定，M0 记录可用性；比赛测试包可如实记录未签名及安装步骤，不把未签名说成已签名。公开发行前完成相应签名与系统拦截体验验收；不要求用户关闭系统安全机制来算通过。

每个平台重置后连续完成 5 次主演示，无需反复重跑所有不相关测试。发生失败则记录并修复，从主流程重新计数。

## 证据记录格式

每次验收保存：任务/AC 编号、commit、OS/CPU、Electron/模型/执行器版本、fixture hash、操作步骤、期望、实际、runId、revisionId、artifact hash、截图/日志位置、执行人与复核人。秘密与客户敏感内容脱敏。

真实模型评估单独运行且有费用上限；普通 PR 可用 mock 测协议，只有带实际模型结果的评估才证明模型能力。断网备用录屏明确标记为回放，现场实时调用记录另外保存。

## 发布与完成门槛

1. AC-01～AC-16 均有证据；所有金额、事务、审批、关键缺项测试通过。
2. 两平台实际安装核心流程通过，数据库和文件恢复有结果。
3. 运行/模型/工具/模板/规则版本可追溯；跨品类与任意目标语言入口成立。
4. 完整源码、lockfile、migration、构建命令、示例配置、样本、许可清单、已知限制可交付。
5. README 命令从干净检出重跑；CI 与 Wiki 检查通过；没有未说明的关键 blocker。
6. 演示脚本包含两工作流、两场景、两轮变化和两类反馈；比赛材料另按赛规核验。

未来可以在授权的发布流程中固定交付 commit/tag；本轮不创建发布标签，不推送，不宣称完成 MVP。
