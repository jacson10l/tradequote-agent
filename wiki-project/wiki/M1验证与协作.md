# M1验证与协作

新工程质量门禁与现有 P0 Wiki 门禁并存，不能用代码测试替代知识页同步。Biome 只检查正式工程，不批量重写历史实验或 Wiki 工具。strict TypeScript 同时检查四个包、UI 与测试；模块边界脚本检查 import/export/require/dynamic import，阻止 renderer 依赖 Node/存储/领域实现，阻止纯领域依赖平台与数据库。

## 分层验证

- Vitest：strict DTO/worker 消息拒绝、受限 patch/schema、领域旧版本与身份边界、SQLite 重开/幂等/冲突/事务回滚/迁移、ArtifactStore 内容与路径安全。
- React Testing Library：真实表单交互、无效输入不调用客户端、保存后刷新、冲突提示及重载。mock 只用于组件测试，不替代桌面存储验收。
- Playwright Electron：构建后启动实际 Electron，隔离临时 userData；真实 UI 创建、第二操作制造冲突、bridge 拒绝额外字段、重新读取、重启恢复、禁用审批与窗口收窄测试。截图保存在忽略目录。参考 [Playwright Electron API](https://playwright.dev/docs/api/class-electron)。
- Wiki：生成 → 只读 check/lint → `pnpm wiki:sync --base 32d7e8c90a7ec4dce1966fdf6e2a73c0b4066826` → 维护工具回归。任务必须记录实际结果，完成前再跑最终只读门禁。

本轮初始实现已跑通 10 项 Vitest 与 1 项实际桌面 E2E；最终复核及新增检查以任务验证记录为准。构建中发现 preload 旧 inlineDynamicImports 配置产生弃用提示，已换为当前 codeSplitting=false；Biome 配置也按实际安装版本迁移。jsdom 版本保留固定 Node 兼容组合。

## 兼容性修正与增量检查

实际 TypeScript 7.0.2 的默认 JS 导出仅含版本，不支持旧 createSourceFile API；边界检查改为精确固定 @babel/parser 7.29.9 的 TypeScript/JSX AST，并补两项反向测试，覆盖裸 Node 内置包、require、动态 import、TS import-equals 及跨包源码绕过。保持 TypeScript 7 类型检查不变。开发 E2E 使用本地 5179 固定端口并真实保存工作区；electron-vite CLI 不接受 --port，已将端口配置放入 renderer.server，最终同时验证 dev 与构建产物。

干净副本首次复现发现 Electron 44 延迟准备可执行文件，electron-vite 直接读取 path.txt 导致 Electron uninstall。修复为 postinstall 显式 require Electron 并校验可执行文件，再重建原生 SQLite。E2E 服务器改为独立 Vite renderer config；electron-vite 的 rendererOnly 实际仍启动桌面，因此不再用于测试服务器。失败证据保留于 [初次复现](../raw/m1-initial-validation.json)，最终结果另存。
