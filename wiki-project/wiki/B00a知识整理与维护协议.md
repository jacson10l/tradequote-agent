## 冻结整理输入和模型提案

KnowledgeBuildInput 固定 operation=create/revise/merge、1～20 个唯一 sourceRevisionId/artifactHash、目标 kind/locale/scope、可选知识基线 revisionId/contentHash/sourceSetHash/documentId/expectedVersion、最多20个关联 revision、instructions 和预算。create 无 base，新文档从 v1 开始；revise/merge 必须有 base，预算只允许1个下一候选，merge 还需固定关联知识。基线 ID 是不可变版本，服务核实工作区和实际 hash/版本，不能把 relatedRevisionIds 当任意读取权限。

maxCandidates 为1～10；每 attempt 的预算为最多1～5次模型调用、1000～120000ms 总耗时、1024～128000个 UTF-8 输出字节。宿主可设置更小上限，不能自行扩大冻结预算。调用前、流式接收和提交前分别检查，超时用 MODEL_TIMEOUT，输出/调用超预算用 MODEL_INVALID_OUTPUT；无候选提交。retry 是显式新 attempt，重新从冻结输入执行，预算计数清零；不会无限自动重试或由模型安排下一轮收费任务。

模型只输出 KnowledgeBuildProposal：proposalKey/sectionKey/ruleKey 为有界临时字符串，正文、段落范围、允许来源 revision 的位置与 fact/inference、结构化规则内容、关系及 merge/conflict 建议。所有对象 strict，不接收新权威 UUID、contentHash、sourceSetHash、ruleId、审核/发布/lint事实或凭据。可回传宿主允许集合中的现有 sourceRevisionId；不能伪造 human_note。现实 validity 只能 unknown，fact/inference 都是候选声明，不等于已核实事实。

ProposalExchange 检查来源和关联 allowlist、规则/非规则区别、段落键、正文范围和建议引用。位置仍为冻结字符串的半开 UTF-16 范围；宿主进一步读取真实原件校验长度/代理字符、hash、来源状态、权限和关系，再分配权威 UUID，并把局部键映射为 P0 section/reference/rule 身份。模型正文不作为新原始来源。模型声明与 P0 来源/现实有效性最终由人工对照审核，不能以“整理 completed”自动批准。

run.sourceSetHash 与 completion.inputSourceSetHash 固定**整个允许来源集合**，算法沿用 P0 排序去重后的来源版本/hash canonical JSON。每个候选自己的 sourceSetHash 对**实际使用子集**计算；完成回执同时列出每候选的来源 pins，必须是冻结输入的非空子集。多个候选可以各用不同子集，不能为了让 hash 相等而虚构未使用引用。候选及原件/正文/摘录 hash 必须由宿主按 P0 完整性规则计算验证。

## 整理运行、恢复与原子候选提交

KnowledgeBuildRun 独立于旧 AgentRun，包含 workspace/runId/原 start operationKey/runVersion、原始 start command、冻结 sourceSetHash、attempt/执行票据、usage、检查点、完成回执与公开错误。不会填写 quoteId/committedRevisionId 或修改旧 AgentOperation。runVersion 每次状态变化递增；attempt 历史、检查点事件序列全局追加，不能清除旧失败证据。

| 操作 | 允许转换 | 权威约束 |
|---|---|---|
| start 内部执行 | queued→running | 新 attempt 的宿主执行票据，模型不持有写入权限 |
| cancel | queued/running→cancelled；任意终态原样回读 | 事务撤销当前票据有效性并阻断晚到结果；没有独立 cancelling 状态，不宣称 Provider 已停止网络传输 |
| retry | failed/interrupted/cancelled→queued | 显式人工操作；attempt+1，票据/usage/非权威进度重置，冻结 command/source hash 不变，事件序列继续 |
| 启动恢复/worker 丢失 | queued/running→interrupted | 先检查已提交回执；无提交才记 interrupted 和公开错误，不自动发模型请求，不复用旧票据 |
| 前置检查/模型失败 | queued/running→failed | 保留公开错误及原attempt；completed不可被迟到失败覆盖 |
| 候选提交 | running→completed | 同一 run/attempt/operationKey/当前票据；原子提交非空完整候选批次、回执、run/事件/幂等/outbox |

KnowledgeBuildTransition 验证固定身份/输入、状态表、版本、attempt 和迟到取消语义。它不是运行调度器；宿主必须在实际数据库写入时对 session/attempt/执行票据进行 fencing，仅有 runVersion 字段不能阻止旧 Worker。completed 不得 retry 或改成 cancelled/failed；提交成功但响应丢失，恢复及同键重放先取原回执，不降级为 interrupted。

检查点仅存 phase、proposalKeys、lastEventSeq，不含原件、prompt、Key、原始响应或堆栈。失败/中断必须有有界公开错误，completion=null；取消也不能带已提交候选。完成回执绑定 workspace/runId/attempt/start operationKey/executionTicketId、原输入集合 hash、receiptId/提交时点和唯一 candidateRevisionIds；每候选保留 proposalKey、document/version、contentHash/sourceSetHash、实际来源 pins 与 literal candidate 状态。completed 必须完整、唯一、非空、未超预算，不能把已审核/发布版本当新候选。

KnowledgeBuildCandidateWriter.commit 是**宿主内部同步事务参与端口**；prepared 候选含完整 P0 WikiRevision/expectedVersion 和局部 proposalKey，不暴露为 renderer/model 命令。CommitExchange 对比当前运行、验证检查点、票据/OCC、工作区、目标/来源允许集合、文档父版本和批次数；A/C 仍须在事务内读取真实 run/来源/知识基线并再验完整性和资格。不可变 blob 先异步写并核验，不能跨 await 占用 SQLite 事务。随后同连接一次提交全部未审核候选、完整回执、run完成、幂等/outbox。DB 失败没有部分候选；孤立 blob 按 P0 宽限期回收。索引失败不推翻已提交完成事实。

## 整理命令与分页

所有命令采用 P0 strict read/write envelope 和 WikiHostContext，workspace/actor/origin/now 来自宿主。写请求幂等作用域为 workspace；摘要含 method、规范化 payload、actor/origin，不含 requestId/now。start 的目标、来源/基线、说明和全部预算都进入原操作指纹。控制请求有独立幂等键与 expectedRunVersion；先在当前权限下识别同键回放，再对新请求做 OCC，避免第一次递增版本导致自身重试冲突。原start的接收回执保持不可变，后续通过get查询当前运行；内部完成回执按(workspaceId,runId)唯一去重，不能覆盖最初start幂等结果或重复创建候选。同键异参 IDEMPOTENCY_CONFLICT，旧版本/失效票据 REVISION_CONFLICT，非法状态/越权 ACTION_NOT_ALLOWED。

| method | 请求 | 成功 kind | origin |
|---|---|---|---|
| knowledgeBuild.start | KnowledgeBuildInput | knowledgeBuildRun | human_ui |
| knowledgeBuild.get | runId | knowledgeBuildRun | 三类 |
| knowledgeBuild.list | limit、cursor | knowledgeBuildRuns | 三类 |
| knowledgeBuild.cancel | runId、expectedRunVersion | knowledgeBuildRun | human_ui |
| knowledgeBuild.retry | runId、expectedRunVersion | knowledgeBuildRun | human_ui |

list 由宿主绑定工作区/快照候选集，runId ASCII 倒序，afterRunId 排他；新运行不插入旧快照。所有后续非终游标包括空页都必须严格减小，固定 snapshotId，不因时点变化换工作区/快照。快照过期返回 REVISION_CONFLICT，未知 run 返回 NOT_FOUND。重试不会偷偷替换来源为 latest；执行/提交前原件失效则 SOURCE_EXPIRED/SOURCE_CONFLICT/MISSING_FACTS/ACTION_NOT_ALLOWED，历史可回读不授权新整理。

## lint、问题与人工处理

2026-10-23 接口适配补充：公共 `KnowledgeLintReviewInputExchangeSchema` 接受 `{report,input,context}`，其中 input 原样复用 P0 `WikiReviewInputSchema`，context 仅由宿主提供。A 在审核事务中按 lintReceiptId 载入真实已存完整报告后，可先检查人工来源、同工作区、报告不晚于宿主时点、receipt/revision/contentHash/sourceSetHash 全部一致，再构造审核决定。完整无阻断报告才允许 approve；blocked/partial/failed 可记录 reject，不能批准。原 `KnowledgeLintReviewExchangeSchema` 继续核对最终审核决定的完整 receipt（包含 policyVersion/checkedAt）。这两个校验不接收 renderer 自造的可信报告，也不替代生命周期 OCC、当前来源资格、报告存储或人工实际操作；A 的正式 lint/review/publish 服务仍待完成。接口反例与本轮 Windows 证据见 [[B01-谱系账本适配与P1回执]]、raw/b01-p1-interface-validation.json。

KnowledgeLintReport 绑定 P0 WikiLintReceipt 的 workspace/revision/contentHash/sourceSetHash/policyVersion/时点与 reportId。覆盖必须完整列出 source_integrity、section_references、relations、scope_validity、source_updates、duplicates_conflicts、orphans 七类，每类 passed/issues/unknown/not_run，问题含稳定 issueKey、检查类别、严重度与固定段落/来源身份。确定性检查与人工/模型未确定的语义冲突分别如实标注，不能宣称穷尽。

status=completed 必须无 unknown/not_run；有 block 时 receipt=blocked，否则 passed（可有明确 warning）。partial/failed 的 receipt 必须 unknown；失败保留公开错误。保存 failed 报告后 getLintReport 成功回读只表示读到失败事实，不代表检查通过。不能用遗漏检查、无来源事实、已知冲突或占位结果获得 P0 可批准 receipt。

MaintenanceIssue 固定 workspace/issueId/issueVersion/dedupKey、确切 source/knowledge/consumer 版本与 hash、类型/严重度/证据和发现时点。去重键由宿主对“工作区＋固定目标身份/版本＋问题种类＋触发事实身份”的规范化集合计算 SHA-256，排除发现时间/请求键；同一问题重扫更新发现证据/时点而不创建重复任务，原事件保留。不能由模型自报去重/解决事实。

状态 open/in_progress/resolved/dismissed；只有人工可 start_review/resolve/dismiss，expectedIssueVersion 做 OCC，actor/time 来自宿主并追加对应生命周期事件。resolve/dismiss 必有已存执行证据；新建候选只算 in_progress，真正解决须核实新发布/来源复核/撤回等对应事实。dismiss 只关闭处理项，不解除来源/知识的实际阻断，不恢复旧审批。处理不得编辑旧知识/报价来消除影响。维护列表按 issueId 升序、绑定 workspace/查询/快照，空页游标仍须严格前进；类型/状态过滤不能改变游标绑定。

## 影响分析与索引恢复

analyzeImpact 是产生不可变报告的写命令，固定触发的来源/知识版本/hash、原因及来源更新时的新 revision。宿主核实同一来源的新旧关系，不接受 self-replacement。报告固定 workspace、snapshotSeq/时点，扫描该工作区在此序列上的来源→知识→消费全图；未实现/断链/未知消费者状态明确 partial/failed，不把未扫描当空集合。

completed 只有完整总数且无 unknownReasons；partial 的 totalItems=null 且明确缺失范围；failed 保留错误/未知总数，不返回伪造影响项。getImpact 只回读已存报告，并按 itemId 升序稳定分页/排他游标，绑定 reportId，空页亦严格前进。有准确总数的首个终页必须返回全部结果；首个非终页不得在全部已返回时伪称仍有更多。续页可空终止，不能用首个空终页隐藏已知影响。每个影响项固定目标版本及 viaKnowledgeRevisionIds；消费者还必须带 consumptionId 和 draft/final/unknown 状态。未完成草稿可提出 requiresReview；最终历史仅报告影响，不改写内容/金额/审批，未知状态不得推断“没有影响”；出现未知消费者的页必须归入partial/failed，不能包装为completed。宿主按影响事实生成去重复核项，B 的正式报价复核/检查适配另验收。

keyword 与 markdown_view 两种投影分别有 generation、authoritativeSeq/indexedSeq、missing/ready/stale/rebuilding/failed。ready 须完整追上权威序列且 generation>0；缺失/失败不是正常空列表。rebuildIndex 固定 expectedGeneration/expectedAuthoritativeSeq，宿主先异步构建/校验新视图，再持有当前 rebuildId/目标生成代的事务中原子切换。重建回执绑定工作区、index、request seq/生成代/operationKey；新事实在构建期间出现时结果可 stale，不能假称 ready。IndexCommitExchange 拒绝旧任务覆盖较新任务/生成代，并要求indexedSeq不低于切换前已覆盖序列；若当前索引已前进到重建快照之后，宿主先追平再切换，或明确冲突重建，不能倒退后悄悄补齐。切换不改变 authoritativeSeq 或来源/知识/消费历史。崩溃先核实已提交切换回执；否则 interrupted，人工新动作重建，旧票据无效。
