# 服务器演进与风险

首版实现单机闭环，同时保留应用服务、存储和通信的替换边界。后续服务器共享是单独的开发阶段，不能描述成“换一个连接字符串就完成”。

## 首版必须保留的边界

- 领域代码只处理数据、规则和结果；不读 Electron、process.env、文件路径或 UI。
- 请求使用稳定 ID、decimal 字符串、明确错误、版本和幂等键，可映射 HTTP。
- 数据访问走 repositories/UnitOfWork；文件访问走 ArtifactStore；模型走 ProviderAdapter。
- 本地工作区 ID、实体 ID、来源/快照 hash 在迁移后仍可识别。
- 客户端显示状态来自业务服务，不能以本地按钮状态或聊天文案表示批准。
- 单机角色切换清楚标识为演示能力；日志不声称证明了真实主管身份。

首版不预建空 HTTP 服务、未使用的云数据库实现、双向同步引擎或租户系统。接口只抽象已经存在的职责，避免形成大量没有第二实现且没有测试价值的通用框架。

## 分阶段迁移

| 阶段 | 工作 | 验收门槛 |
|---|---|---|
| S1 服务化 | 将 application/domain 放入 Node 服务；新增 HTTP Client 实现与服务端 DTO 校验；桌面仍管窗口和本地文件选择 | 同一份领域/契约测试在本地和 HTTP adapter 上通过 |
| S2 统一身份与权限 | 登录、组织/岗位权限、服务端 actor、资源授权、审计；关闭可冒充身份的角色切换 | 模型或客户端伪造 actor/角色被拒绝；采购成本与销售字段按权限隔离 |
| S3 共享存储 | PostgreSQL repository、对象存储、服务端任务队列；共享事务与幂等记录 | 两客户端同时修改同报价，一方冲突；不能重复审批/保存 |
| S4 数据迁移 | 冻结本地写入、导出 manifest、导入服务器、比对 ID/hash/数量/金额/引用 | 全量核对通过再切换；保留本地只读备份与回滚方案 |
| S5 真实协作 | 岗位分配、任务通知、服务端版本事件、文件上传、模型密钥集中管理 | 两真实用户完成询盘→采购确认→审核，权限和引用不丢失 |
| S6 后续能力 | 自动知识影响分析、批处理、邮箱连接、多商家隔离 | 各自独立需求与安全/业务验收，不自动加入首版 |

Node 服务框架与 Postgres ORM 版本在 S1 依据当时实现再定；不在首版提前绑定。SQLite TEXT decimal 迁移到 NUMERIC 时必须核对精度和 canonical serialization，不能假定跨引擎 hash 自动相同。

桌面“服务器模式”建议先在线编辑，离线仅查看明确标记的缓存；离线双写与冲突合并另立项目，不能把数据库文件放共享盘来代替服务端。

## 数据迁移协议草案

1. 创建只读迁移快照，manifest 记录 schemaVersion、workspaceId、实体数量、每份原件/报价/产出 hash。
2. 导出业务数据、版本、审批、引用与原件；API Key 不导出。单机 ActorProfile 标记为历史记录来源，不能直接变成服务器账户。
3. 服务端 dry-run 校验 ID 冲突、Decimal、币种单位、版本链、原件缺失；返回逐项错误。
4. 在新的组织空间导入，核对数量/金额/引用，验证若干旧 PDF 和修订案例。
5. 业务负责人确认后切换客户端 endpoint；旧工作区只读。保留可恢复备份，禁止本地与服务器继续各写一套。

## 风险与处理责任

| 风险 | 触发证据/表现 | 处理与 owner |
|---|---|---|
| Solivio 耦合迁移超过收益 | 必须拉起 Next/Postgres 才能使用候选模块 | M0 记录依赖，抽取纯逻辑/交互或改写，A/B |
| Harness 迭代与分发 | preview；本机裁剪工具已通过，SDK 无单会话取消，双平台打包待验 | 固定版本、每个活动 run 独占进程、自有 profile 与工具断言；未过必需关卡则换执行器，C；见 [M0](技术验证记录.md) |
| 平台/ABI | SQLite `.node`、解析器、字体在安装包中失败 | M0 双平台探针，M6 实际安装；原生依赖不靠跨编译成功证明可用，A/C |
| 文件抽取错误 | 合并单元格、公式无缓存、PDF 列顺序错误 | 保留位置与原件、人工预览确认、错误行，不默默生成价格，A |
| 资料或规则不完整 | 单位/成本/适用条件无依据 | 不完整草稿与明确确认任务；业务资料提供人复核，A/B |
| 任意语言质量差异 | 模型无法可靠翻译、额外承诺、缺字/RTL | 事实绑定、术语、人工审核、已验证矩阵与错误反馈，B/C |
| 旧版本或重复写入 | 并行手改、模型重试、崩溃恢复 | expectedVersion＋事务＋幂等＋outbox，B/A/C |
| 资料内容被当指令 | 文件要求改模型 endpoint、执行 shell 或批准报价 | 数据/指令隔离、工具 allowlist、服务端状态检查，C |
| 未来迁移困难 | 业务代码直接读本地表/文件或持有 Electron 类型 | 边界检查、ports、迁移演练；M1 起拦截，三人 |
| 无业务验证资源 | 只有合成数据，没有人核对真实规则 | 标明工程演示边界，准备资料清单，B 组织 |
| Windows/签名资源未落实 | 只有 Mac 构建或无实际目标机 | M0 指定测试资源；未完成实际安装不得标记双平台通过，C |

上述是当前可识别的工程风险与应对，不表示问题已经发生或已解决。风险关闭必须链接到实测记录。
