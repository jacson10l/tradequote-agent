# 工程Wiki要求对照

已从头到尾重新阅读用户文件。以下按原章节逐项核对；本轮范围为现有工程 Wiki，既有用户选型优先，参考文档不会扩张为发布/部署授权。

| 原章节/要求 | 本轮落实 | 证据/边界 |
|---|---|---|
| 1 触发、路径、增量与授权 | 只写 wiki-project，保留现有工程 | 根规则/源码/原件不改，无提交发布 |
| 2 预检、Git、文件保护 | 读取规则/README/manifest/DESIGN/锁文件，固定工作区基线 | 来源清单/ingest-baseline；无 CI/桌面构建配置，记为不存在 |
| 3 UI 决策与来源 | 沿用用户 Mistral 选择，补正式 ADR | [[0001-Mistral工作台风格]]；代表界面验收仍未实现 |
| 4 选型、版本与边界 | 原方案＋实际实验版本分开记录 | [[0002-上游复用方式]]；Rust 不适用，Electron 为目标未构建 |
| 5 同项目 Wiki 与目录 | 根 wiki-project，完整实质内容与 Obsidian 配置 | 索引、11 类知识、tasks/decisions/raw/generated/scripts |
| 6.1 四层与来源 | 原始证据、语义知识、任务决定、规则分层 | source-manifest 明确当前与历史，证据分类 |
| 6.2 必读范围 | 深读 M0 源码/测试/注册与边界，锁文件范围如实标注 | [[知识库可靠性与覆盖范围]]；未读 node_modules 不冒充覆盖 |
| 6.3 页面 schema | 规范旧页枚举/sources，所有语义/生成页元数据 | lint 检查日期、状态、来源、verified 代码证据；语义双链至少两条 |
| 6.4.1 文件清单 | 稳定排序的路径/类型/行数/总量 | [[代码清单]] |
| 6.4.2 内容快照 | 每文件 SHA-256＋固定采集基线 | [[源码快照]]；维护工具另留指纹 |
| 6.4.3 全量覆盖 | 每个纳管文件分配真实职责页 | [[源码覆盖矩阵]]；新增漏分类失败 |
| 6.4.4 机械能力 | scripts/deps/env 名/tool/route/SSE 清单 | [[命令与运行时清单]]；无产品 IPC/数据表/迁移/作业，明确不适用 |
| 6.4 排除与基线 | 排除 Wiki/依赖/缓存/敏感路径，不跟随 symlink | 负向测试；--check 不更新内容/时间/HEAD |
| 6.5 文件/schema/链接/覆盖 | 实际 lint CLI，先生成器检查后其余门禁 | 负向样本验证断链、孤立页、错误行号、重复名、错误元数据 |
| 6.5 秘密/个人信息 | 纳管源码/工具/自有知识规则检查，报错不回显值 | 合成 token/JWT/私钥/email 测试；原始外部归档按 hash 保护 |
| 6.5 漂移/占位/done | 漂移非零；未替换占位报错；done 须验证记录 | 独立临时副本反向测试 |
| 6.6 任务/ADR/恢复 | 六部分任务、五部分 ADR、索引/状态/context/log | [[2026-10-21-工程Wiki补齐]]，M0 任务继续 active |
| 6.7 日常循环 | 真实 CLI 的 ingest/query/lint/task 流程 | [[Wiki 工作流与任务记录]] |
| 7 实施顺序 | 本轮补齐知识门禁，不再延期 | 产品核心闭环仍按 M0→M1 顺序 |
| 8.1 应用验收 | 本轮未改业务源码，不重跑原模型探针 | 保留既有实测；不能称产品初始化完成 |
| 8.2 Wiki 验收 | 执行生成/check/lint、语法、反向测试、Git 空白检查 | [验证记录](../raw/wiki-validation.json)，最终落文后再 check/lint |
| 8.3 完成界限 | Wiki 任务可在门禁通过后 done；M0/MVP 保持未完成 | [[项目状态]]；未初始化产品不伪称完成 |

页面/映射/校验脚本存在不等于成功，实际退出码以验证记录为准。当前工作区仍有既有未提交文件；基线是采集锚点，Git 分支/HEAD/差异在最终交付单独报告。
