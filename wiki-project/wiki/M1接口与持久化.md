# M1接口与持久化

工作区切片之后已增加 [[M2真实报价V1]] 的场景、CSV 与手工草稿契约；完整报价修订/Agent 契约仍按 03/04 页逐步实现，T00 三人评审没有代签。

## 共享契约

Zod strictObject 拒绝未知字段。工作区 DTO 为 id、name、version、createdAt；名称去首尾空白、1～80 字。查询命令 workspace.get 携带 schemaVersion=1/requestId；create/rename 另需 idempotencyKey，rename 必须提供 expectedVersion。请求 method 判别联合，不接受任意 channel。响应成功含 data/warnings/evidenceIds，错误含 code/message/retryable/issues 及可选 currentAggregateVersion。当前工作区错误码为总目录子集；issues 保留完整结构，尚无报价字段问题生成。

边界分层：preload 校验输入和响应；Main 校验调用来源及 method/channel 一致；WorkerRequest/Reply 校验消息；应用服务再次校验并拒绝非 human_ui 的工作区操作。身份由宿主注入，不允许 renderer/model 在 DTO 写 actor/origin。桌面 Client 与业务端口分离，未来 HTTP adapter 可复用契约。

typedPatch 已扩展为九类显式操作，详见下方契约增量；decimal 保持字符串，不能写 total/approval。JSON Schema 转换有独立测试，但尚未送真实模型，不宣称 DeepSeek 兼容性已验收。价目表 V1 金额已在 domain/trade.ts 实现，九类 typedPatch 尚未全面执行；当前三类受限修改见 [[M4模型与报价修订]]。readonlyMockClient 显式拒绝写入，不以 fake 保存成功掩盖真实服务尚未实现。

## 事务与迁移

WorkspaceRepository/ArtifactStore 为端口，纯领域不依赖 Electron/Drizzle。transitionWorkspace 拒绝已有工作区的重复新建及旧版本修改；不原地修改传入对象。SQLite adapter 使用 Drizzle 读取/写入工作区，在 immediate 事务中完成工作区、outbox、幂等三者提交。requestId 不进入请求哈希，因此同一幂等键不同传输请求可回放原结果；method/payload/宿主上下文变化则报 IDEMPOTENCY_CONFLICT。失败事务不留下部分数据。

初始迁移包含 workspace/source/job/idempotency/outbox，启用 foreign_keys、WAL、synchronous=FULL。迁移 2 已追加 scenario_revision/catalog_batch/catalog_product/quote_v1 四表并投入实际用例；原 source/job 基础表仍未消费，CSV 原文与来源暂存在 catalog_batch，后续通用导入须迁移整合；尚无任务执行器或恢复服务。outbox 已保存事件与上下文，尚无推送/消费进度；界面通过查询失效刷新。迁移与 user_version 同事务，新于应用的数据库拒绝打开；测试覆盖失败迁移回滚。

ArtifactStore 以 SHA-256 ID 读写文件；先临时文件后同目录硬链接发布，重复内容验证哈希，读取拒绝非法 ID、路径穿越、符号链接与损坏内容。该服务尚未暴露 renderer 或导入 UI。Windows 文件系统行为保留平台验收，不将 macOS 测试外推。备份/恢复与更严格的跨平台文件持久化保证留在后续任务。

## T11 契约基础增量（待 T00 人工评审）

`values.ts` 提供 DecimalString、Quantity、Money、五态 Fact、SourceLocation 和 Evidence；货币字段为三位大写代码，实际是否在企业币种/单位目录中必须由后续服务确认。Locale 使用 Intl 的 BCP 47 语法校验，支持 en/de/zh-Hans-CN/ar/ja-JP/pt-BR 等任意合法语言标签，不把两个语言或市场设成产品范围。金额/数量仍是字符串；missing/not_applicable 必须有原因且不接受 value，confirmed 必须关联证据，proposed 可以没有证据。CSV 行/PDF 页从 1 开始；DOCX 必须提供段落或表格单元格；文本范围不能倒序。不制造扫描输入的来源位置。

`quote.ts` 实现 setQuantity、selectProduct、selectPrice、setPackaging、setDeliveryTerm、setCommercialTerm、addLine、removeLine、setPricingPolicy 九类 strict patch。setQuantity 从旧 `{quantity:string, unit:string}` 统一为 `{quantity:{value,unitId}}`；旧布局样例不调用此接口，正式测试和 mock 已一起迁移。选择商品/价目表/策略只能传 revision ID；包装可以附每包数量；交货术语为术语与可选地点；商业条款为有界 key/value。批量 1～50 项，拒绝 total/approval/actor/contentHash 等注入。零数量结构可表达，业务是否允许须领域验证，不能以 schema 通过代替可报价结论。

QuoteRevisionInput 固定 quoteId/baseRevisionId/expectedAggregateVersion/typedPatch/reason；ApprovalBinding 固定 revision/contentHash/bundleId/bundleHash 与人工备注。schema 存在不意味着批准服务已实现，也没有向 Agent 注册审批工具。`patchToolJsonSchema` 从同一受限补丁导出 draft-7，仍需 T40 真实供应商兼容性验证。

`events.ts` 将接口页九种 RunEvent 从 payload:unknown 转为按 type 判别的 strict payload，包含版本创建、产出、问题、取消已提交版本引用等；事件有 schemaVersion/eventId/runId/seq/timestamp。artifactId 是 OutputArtifact 业务 UUID，文件 hash 仍由 ArtifactStore 独立管理。`errors.ts` 统一 18 个公共错误码，避免响应与运行失败事件分叉。尚无 run 持久化/事件发布/重连消费；本轮只补类型、校验和模拟夹具，不增加 IPC channel，不返回伪造的报价保存或 Agent 成功。

来源：packages/contracts/src/values.ts、quote.ts、events.ts、errors.ts、mock.ts；测试为 foundation.test.ts。已建的 workspace/source/job/幂等/outbox 初始迁移与文件仓库不变，没有改写已提交迁移。后续 T11 仍需各领域查询/命令/端口随 M2～M4 实现落地并通过实际三人评审。
