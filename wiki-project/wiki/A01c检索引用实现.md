# A01c检索引用实现

A01c 在 codex/a01c-knowledge-search 实现 [[B00a知识Wiki公共协议]] 的 WikiService 存储端口与检索/引用/消费读写路径：来源与知识版本暂存、已发布知识检索、逐来源引用解析、报价/产出消费登记。这是 A01 五切片中"检索引用"切片。随后 A01e 在同文件补上 lint 回执落库与人工审核/发布/撤回（review/publish/withdraw），把 P1 契约落地为真实服务；lint 成功不自动发布。

## 当前实现

- 服务 createWikiService（packages/domain/src/wiki.ts）：先 WikiCommandSchema 校验，再按 wikiMethodOrigins 做来源门禁（source.stage/review/publish/withdraw 仅 human_ui；wiki.stage 允许 agent_tool；读方法三来源开放），随后分发到同步存储端口 WikiStore。公开 execute 为 async，内部 store 全部同步，因为 better-sqlite3 事务不能跨 await。
- 存储 SqliteWikiStore（packages/infrastructure/src/wiki-store.ts）：
  - 暂存 source.stage 计算真实 UTF-8 sha256 artifactHash（content-addressed，artifactId===artifactHash），按 source_id 追加 version；wiki.stage 计算 contentHash=sha256(markdown) 与 sourceSetHash=sha256(wikiSourceSetPayload(sourceRefs))，写入不可变 knowledge_wiki 与候选 lifecycle。写事务 immediate + 幂等重放 + outbox 事件与 TradeStore/A01b 一致。
  - 检索 search：JOIN knowledge_wiki+knowledge_lifecycle 只取 state='published'，先按 document 取最新再过滤 scope/locale/kind/keyword/validity；过滤发生在去重之后，因此最新版本不匹配时整篇丢弃、绝不回退旧版本；validity 仅 status='confirmed' 且落在半开区间内生效。分页游标固定 snapshotId/queryHash 并严格前进，换查询 hash 的游标返回 REVISION_CONFLICT。
  - 引用 resolveCitation：按 citationMatches 逐段核对 revision/section/sourceRefs 身份与 hash，回读全部引用来源并核对 workspace/sourceId/version/artifactHash，返回逐版本 sourceStates 与 eligibility。eligibility 对知识侧核对 published/当前发布头/有效期，对来源侧逐版本核对 state active、来源有效期（expired/not_yet_valid/conflict/unknown）以及来源版本头（同 sourceId 已存在更高版本即 source_updated）；purpose=new_reference 只要任一依据失效即整体返回 SOURCE_CONFLICT 失败，不得返回 ok=true/eligible=false；purpose=history 可回读并给原因。
  - 消费 registerConsumption：同一事务内重放幂等并逐引用复核 lifecycle='published'、citationMatches、来源 state='active'，写不可变 consumption 行；getConsumption 按 consumer kind+revisionId 回读。
  - review 人工审核：绑定 revisionId/contentHash/sourceSetHash 与已存 lintReceiptId，构建 WikiReviewDecision 并按 WikiReviewDecisionSchema 校验（lintReceiptId===receiptId、workspace/revision/两 hash 匹配、approve 须 outcome==="passed"、decidedAt>=checkedAt），candidate→approved/rejected；同请求 hash 幂等回放。
  - publish 显式发布：核对 state=approved、审核 approve、revisionId/两 hash/lifecycleVersion 一致、decidedAt<=now，写 PublicationEvent(type="published")，approved→published；lint 成功不自动发布。
  - withdraw 撤回：核对 state=published、审核 approve、decidedAt<=now，写 PublicationEvent(type="withdrawn")，published→withdrawn（不可逆，保留原发布/批准事件）。
  - lint 回执 runLint：对知识版本跑真实 lint，重算 contentHash/sourceSetHash、逐来源解析并核对 workspace/sourceId/version/artifactHash/摘录/来源 state，产出 policyVersion/outcome 回执写入不可变 knowledge_lint；同一 revision/hash/checkedAt 幂等回放已有回执。
- 迁移（packages/infrastructure/src/migrations.ts）：新增 knowledge_source、knowledge_wiki（不可变触发器）、knowledge_lifecycle、knowledge_consumption（不可变触发器）四表，A01e 追加 knowledge_lint（不可变回执表，`knowledge-wiki:8`）；在三方谱系收敛中知识四表记为 `knowledge-wiki:6`、lint 回执记为 `knowledge-wiki:8`（与 C 的 `c-run:6/7` 区分），B 的检查报告为 `check-report:7`，账本以 (lineage,version) 主键记录，见 [[0029-迁移谱系统一与拒绝边界]]。
- 接线（packages/infrastructure/src/index.ts）：SqliteWorkspaceRepository 新增 executeWiki(command, WikiHostContext) 与 runWikiLint(revisionId, context)（维护入口，直接落库回执，不经 WikiCommand 路由），导出 SqliteWikiStore；domain 导出 createWikiService。
- 测试（packages/infrastructure/src/wiki-store.test.ts）：A-W06-1/2、A-W07-1/2/3/4、A-W08、A-W09-1/2/3 共 10 项，覆盖检索不回退旧版本、分页游标固定、多来源引用闭环、来源过期/来源更新后的引用资格、消费事务复核与幂等、来源/知识暂存幂等与来源门禁，以及 lint→审核→发布→撤回全链、回执绑定与 hash 门禁、状态守卫与乐观并发；检索/引用输入用 seedCandidate 直接写 lifecycle 构造，发布路径由 A-W09 覆盖。
