# A01c检索引用实现

2026-10-23 联调更新：远端已存在dd42b05；以下原交付的“未复跑”是当时记录，当前组合验证见 [[2026-10-23-B01新Wiki存储联调]]。人工审核/发布/撤回仍不可用。

A01c 在 codex/a01c-knowledge-search 实现 [[B00a知识Wiki公共协议]] 的 WikiService 存储端口与检索/引用/消费读写路径：来源与知识版本暂存、已发布知识检索、逐来源引用解析、报价/产出消费登记。这是 A01 五切片中"检索引用"切片，人工审核发布（review/publish/withdraw）依赖 P1 lint 回执，本切片保持 CAPABILITY_UNAVAILABLE。

## 当前实现

- 服务 createWikiService（packages/domain/src/wiki.ts）：先 WikiCommandSchema 校验，再按 wikiMethodOrigins 做来源门禁（source.stage/review/publish/withdraw 仅 human_ui；wiki.stage 允许 agent_tool；读方法三来源开放），随后分发到同步存储端口 WikiStore。公开 execute 为 async，内部 store 全部同步，因为 better-sqlite3 事务不能跨 await。
- 存储 SqliteWikiStore（packages/infrastructure/src/wiki-store.ts）：
  - 暂存 source.stage 计算真实 UTF-8 sha256 artifactHash（content-addressed，artifactId===artifactHash），按 source_id 追加 version；wiki.stage 计算 contentHash=sha256(markdown) 与 sourceSetHash=sha256(wikiSourceSetPayload(sourceRefs))，写入不可变 knowledge_wiki 与候选 lifecycle。写事务 immediate + 幂等重放 + outbox 事件与 TradeStore/A01b 一致。
  - 检索 search：JOIN knowledge_wiki+knowledge_lifecycle 只取 state='published'，先按 document 取最新再过滤 scope/locale/kind/keyword/validity；过滤发生在去重之后，因此最新版本不匹配时整篇丢弃、绝不回退旧版本；validity 仅 status='confirmed' 且落在半开区间内生效。分页游标固定 snapshotId/queryHash 并严格前进，换查询 hash 的游标返回 REVISION_CONFLICT。
  - 引用 resolveCitation：按 citationMatches 逐段核对 revision/section/sourceRefs 身份与 hash，回读全部引用来源并核对 workspace/sourceId/version/artifactHash，返回逐版本 sourceStates 与 eligibility（published+非 superseded+validity+来源 active 才 eligible）。
  - 消费 registerConsumption：同一事务内重放幂等并逐引用复核 lifecycle='published'、citationMatches、来源 state='active'，写不可变 consumption 行；getConsumption 按 consumer kind+revisionId 回读。
  - review/publish/withdraw 返回 CAPABILITY_UNAVAILABLE（依赖维护协议 lint 回执，见 [[B00a-业务Wiki契约补充]]）。
- 迁移（packages/infrastructure/src/migrations.ts）：新增 knowledge_source、knowledge_wiki（不可变触发器）、knowledge_lifecycle、knowledge_consumption（不可变触发器）四表；在三方谱系收敛中该切片记为 `knowledge-wiki:6`（与 C 的 `c-run:6` 区分），B 的检查报告为 `check-report:7`，账本以 (lineage,version) 主键记录，见 [[0029-迁移谱系统一与拒绝边界]]。
- 接线（packages/infrastructure/src/index.ts）：SqliteWorkspaceRepository 新增 executeWiki(command, WikiHostContext)，导出 SqliteWikiStore；domain 导出 createWikiService。
- 测试（packages/infrastructure/src/wiki-store.test.ts）：A-W06-1/2、A-W07-1/2、A-W08 共 5 项，覆盖检索不回退旧版本、分页游标固定、多来源引用闭环、消费事务复核与幂等、来源/知识暂存幂等与来源门禁；因 publish 未实现，测试直接写 knowledge_lifecycle 把候选提升为 published 来构造检索/引用输入。

## 2026-10-29 A01e 八维护方法（knowledge-wiki:9）

在 S4 公共端口（wiki.lint/wiki.getLintReport）基础上，补齐 B 维护契约剩余八个方法，使 A01e 持续维护切片的方法面完整：`source.withdraw`、`wiki.getMaintenance`、`wiki.resolveMaintenance`、`wiki.analyzeImpact`、`wiki.getImpact`、`wiki.getIndexStatus`、`wiki.rebuildIndex`、`wiki.getIndexRebuild`。全部在 `SqliteWikiStore` 实现并接入 `createKnowledgeMaintenanceService` 路由（`wiki-maintenance.ts` 的 switch 已覆盖十方法）。

- **来源撤回 source.withdraw**：按 OCC（expectedVersion）校验来源未再变化后撤回，同一事务内登记维护问题（dedup_key 去重）；重复撤回/已结案撤回按版本冲突拒绝，不重复写。
- **维护问题 getMaintenance / resolveMaintenance**：getMaintenance 按稳定游标分页（snapshot 固定、严格前进）；resolveMaintenance 按 OCC（期望 state/seq）推进 open→acknowledged→resolved，版本不符报冲突。
- **影响分析 analyzeImpact / getImpact**：analyzeImpact 以权威快照 seq 生成影响报告（覆盖受知识版本影响的知识与消费），消费状态未知记 partial；getImpact 回读报告/条目并分页；无消费时记 completed 且 totalItems 为知识版本数。
- **索引状态/重建 getIndexStatus / rebuildIndex / getIndexRebuild**：keyword/markdown_view 双索引状态，覆盖缺失→就绪→滞后（authoritative_seq > indexed_seq）→重建；rebuildIndex 走 OCC（generation）并写 knowledge_index_rebuild，getIndexRebuild 回读。
