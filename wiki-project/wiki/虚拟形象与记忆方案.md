# 虚拟形象与记忆方案

## 需求澄清方法（grill-me）

本方案在开工前采用 grill-me 方法论（源自 mattpocock/skills 的 `/grill-me`）：先通过连续提问把"载体、能力程度、记忆内容、存储位置、写入模型、容量策略、对话挂载点、审核方式"等设计树分支逐一问清并显式对齐，再落稿。避免"先写代码后才发现理解偏差"的典型失败模式。核心对齐结果见下文"关键设计决策"表。

## 参考案例：dsh-pet

参考开源项目 dsh-pet（PC2005-cloud/dsh-pet，DeepSeek Harness 桌面宠物）作为能力对照，但载体不同：dsh-pet 是独立桌宠进程（单进程 Electron、可多开、上桌面），本方案是现有桌面软件内嵌看板娘。可借鉴点：

- **素材链**：dsh-pet 提供"完整素材生成链"与一百余个透明动画，说明"趴姿小人"可体系化批量产出 sprite 表情/动画，而非单张静态图（对应 Phase 3）。
- **语音**：dsh-pet 支持按住说话录音，作为小人对话的可选扩展（Phase 3）。
- **许可证提醒**：dsh-pet 代码 MIT、素材禁止商用。本方案 AI 生成的看板娘形象用于正式产品前，须确认生成平台授权条款（见"边界与风险"第 4 点）。

## 定位与当前事实

本页是"报价小人"（虚拟形象看板娘）的新目标设计，尚未实现。给 TradeQuote 询报价工作台（`apps/desktop`，Electron＋React）增加一个橙色暖色调、科技感的 2D Q 版看板娘，使其成为产品的品牌门面与轻量对话伙伴，并拥有独立记忆能力。载体就是现有桌面软件本身，不另做独立桌宠进程或窗口。

看板娘是"品牌代言人 + 陪聊伙伴"，**不是**业务报价 Agent；两者职责、数据、上下文严格隔离，不能污染询盘理解/报价/账本/审批的业务语义。

## 视觉基调（已提取自现有源码）

- 主色 `#cc3a05`（动作橙）与 `#fa520f`（顶部强调橙），暖底 `#fffaeb`/`#fff8e0`/`#fff0c2`。
- 品牌图标为圆角橙色方块内白色报价单 + 上升折线箭头（`resources/icon.svg`）。
- 字体 Inter / 系统无衬线，克制现代；浅色工作台（Mistral AI 参考风格）。
- 看板娘采用 2D 二次元插画风（清晰描边 + 平涂阴影，无 3D 渲染），Q 版大头小身，中性无性别气质，橙色暖色。

已生成的素材位于 `generated-images/`（含 3D 版、2D 立绘、圆形头像、趴姿透明 PNG）。当前为 AI 生成、含水印，正式使用前需去水印并确认授权。

## 总体架构（三层）

```
┌──────────────────────────────────────────────┐
│  表现层（renderer / React）                     │
│  ├─ DeepSeek 模型头像 → 圆形看板娘头像            │
│  ├─ 趴对话框旁的小人（透明 PNG，CSS 定位贴边缘）    │
│  └─ 小人专属对话入口（独立页/面板）               │
├──────────────────────────────────────────────┤
│  人格与记忆层（新独立模块 "PetMemory"）           │
│  ├─ 固定人设（品牌人格，人工审核，版本化）          │
│  ├─ 会话记忆（流动，自动写，滑动窗口+摘要）         │
│  └─ 存储：独立 SQLite 表 / 独立目录              │
├──────────────────────────────────────────────┤
│  模型层（复用现有 DeepSeek 接线）                │
│  └─ 小人对话 = 独立模型会话，与业务对话隔离        │
└──────────────────────────────────────────────┘
```

## 模块拆解

### 模块 1：视觉层（Phase 0，可先做，零后端改动）

| 项 | 内容 | 位置 |
|---|---|---|
| DeepSeek 头像替换 | 圆形看板娘头像替换 `model-settings`/对话中的模型头像 | `apps/desktop` renderer |
| 趴姿小人 | 透明 PNG，贴对话气泡/面板边缘，可加简单待机动画 | 对话区/工作台 |
| 品牌对齐 | 颜色用 `#cc3a05`/`#fa520f`，暖底 `#fff8e0`，复用现有 `theme.css` | renderer |

### 模块 2：人格与记忆存储（核心新增）

按用户原始需求「在 llm wiki 知识库单独开一个板块」，小人的记忆在**项目知识库 `wiki-project/` 里开一个独立板块**（`wiki-project/wiki/pet/`），随 git 版本管理：

- **人设**：`wiki-project/wiki/pet/报价小人人设.md` —— 固定人格、视觉、性格、口头禅，人工维护、进 git。
- **长期记忆**：`wiki-project/wiki/pet/报价小人记忆.md` —— 对话中沉淀的偏好/称呼/约定，追加式、进 git。
- **运行时会话态**：独立 `pet-memory.db`（有界滚动 + 摘要压缩）承载高频 fact/summary，作为会话缓存；重要长期记忆沉淀回上述 wiki 板块，形成可版本管理的知识。

- 固定人设（品牌人格、口头禅、语言风格）：人工审核 + 版本化，模型不能自行修改。
- 会话记忆（近期对话 + 偏好事实）：免审自动写，有界。
- 建议数据模型（最终以公共契约为准）：
  ```
  pet_persona { personaId, version, content, approvedBy, approvedAt, ... }
  pet_memory  { memoryId, workspaceId, kind(persona|summary|fact),
                content, createdAt, ttl?, ... }
  ```

### 模块 3：小人对话入口

- 独立对话入口（新增类似"只读助手"的侧栏入口），与业务询报价对话完全隔离。
- 复用现有 DeepSeek 接线，走独立会话上下文（不混入业务事件/账本）。
- 系统提示词 = 固定人设 + 检索出的相关记忆。

## 关键设计决策（已与用户对齐）

| 决策点 | 结论 |
|---|---|
| 记忆放哪 | 项目知识库 `wiki-project/` 的独立板块（`wiki-project/wiki/pet/`：人设 + 长期记忆，进 git）；运行时会话态走独立 `pet-memory.db` |
| 小人能力 | 可对话 + 记忆（有性格、记偏好） |
| 记忆内容 | 人设 + 会话记忆都存 |
| 载体 | 现有 Electron 桌面应用内加，不另起独立桌宠 |
| 写入模型 | 独立板块，不照搬业务 Wiki 的人工逐条审核 |
| 容量策略 | 有界（滑动窗口 + 长期摘要） |
| 对话挂载 | 独立对话入口（与业务对话隔离） |
| 人设审核 | 人设人工审核，会话记忆免审自动写 |

## 分期实施

- Phase 0（纯视觉，立即可做）：头像替换 + 趴姿小人贴进 UI，零后端改动。
- Phase 1（记忆存储）：建 PetMemory 独立表 + 人设管理 + 会话记忆读写。
- Phase 2（对话能力）：小人专属对话入口 + 记忆检索注入 + 摘要压缩。
- Phase 3（润色，可选）：待机动画、表情状态联动（思考/报价成功）、语音。

## 边界与风险

1. 小人记忆（人格/会话性质）与业务 LLM Wiki（产品资料/SOP/规则）**不共享索引、不共享审核、不共享数据目录**；守住此边界，避免污染知识/报价语义（见 [[A业务LLMWiki方案]]）。
2. 小人对话同样遵守有界约束（上下文窗口、记忆 token 上限），避免撑爆模型预算。
3. 人物一致性：若要多表情/多姿势且要求同一张脸，须先锁定一张"标准脸"再派生，否则脸不一致。
4. 生成图含水印，正式使用前需去除；商用需确认生成平台授权条款。
