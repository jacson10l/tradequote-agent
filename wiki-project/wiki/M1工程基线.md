# M1工程基线

M0 与 P0 Wiki 规则已提交本地 `32d7e8c90a7ec4dce1966fdf6e2a73c0b4066826`，没有推送。正式工程在 `codex/m1-foundation` 建立；M0 两个 experiments 保留独立 manifest/锁文件，不并入产品 workspace。

## 目录与运行链路

pnpm 纳管 apps/desktop、packages/contracts、domain、infrastructure 四个实际模块。renderer → 窄 preload → Main 校验来源 → BusinessWorker → 业务 Utility Process → 工作区服务 → SQLite 单写入。没有为 M2/M4 建立空包；后续 application 包随更多用例提取，当前 workspace 服务与 ports 在 domain。

正式界面可以创建、读取、重命名本机工作区，退出后重开从数据库恢复。`app.requestSingleInstanceLock` 避免同一 userData 多应用并写。数据库固定于 `userData/workspaces/default/workspace.sqlite`；default 是首版本地槽位，业务 workspaceId 是 UUID，不是未来租户身份。未打包测试可用 TRADEQUOTE_TEST_DATA 指定隔离目录，发布包忽略该变量。

Main 拒绝非主窗口、非主 frame 和非预期 URL 的 IPC，屏蔽新窗口、导航、webview 与权限请求；启用 sandbox/contextIsolation、关闭 nodeIntegration。preload 仅暴露 get/create/rename 工作区三个方法。没有通用 invoke、fs、shell、密钥或数据库接口。主进程不写业务库；业务进程退出后待决请求返回不可用，需重启应用。15 秒超时明确“结果未知”，UI 重试同一操作复用幂等键；没有承诺后台恢复/自动重启已经完成。

## 精确工具链

开发 Node 22.22.0 / pnpm 10.13.1；Electron 44.9.2，React/React DOM 19.3.1，TypeScript 7.0.2，electron-vite 6.0.0 / Vite 8.3.4。新增依赖查询 npm registry 后精确锁定，完整传递树在根 pnpm-lock.yaml。jsdom 选 26.1.0，因为当前 latest 30.1.3 要求 Node 至少 22.22.2，与固定开发版本不同；没有静默提高 Node 要求。

Tailwind 4.3.3、React Router 7.18.4、TanStack Query 5.104.5、React Hook Form 7.90.0 / resolvers 6.0.0、Zod 4.6.7 已接入正式 renderer。React 状态处理样例面板，未增加 Zustand。SQLite 13.0.3/Drizzle 0.45.4 沿用 M0，Harness 没有进入生产依赖。

`pnpm install` 的 postinstall 先显式准备 Electron 可执行文件，再用 electron-builder 对 SQLite 重建 Electron ABI；`pnpm test` 同样在 Electron 的 Node 模式运行 Vitest，避免 Node 22 与 Electron Node 24 两套 ABI 反复覆盖原生模块。UI 组件测试仍为 jsdom，真实桌面由 Playwright Electron 单独验证。打包应用的生产外部依赖只有 better-sqlite3，其余内部 TS 包在构建时打入 bundle。

## 开发与构建

根命令：`pnpm dev`、`pnpm typecheck`、`pnpm test`、`pnpm test:e2e`、`pnpm build`、`pnpm check`。`package:mac`/`package:win` 分别配置 DMG/NSIS，不自动发布；本轮用户暂缓安装验收，配置存在不等于对应安装包已通过。独立真实模型评估尚未移入正式工程，因此没有提供返回假成功的 eval:agent。

electron-vite 分别构建 main/worker/preload/renderer。preload 全量打包为单文件以适配 sandbox；better-sqlite3 留作原生 external。React refresh 的内联启动脚本仅在本地 Vite serve 模式放开，生产 HTML 仍为 script-src self；开发服务器绑定 127.0.0.1。后续需要发布协议、签名、公证和 CSP 扩展时单独评审。

构建参考：[electron-vite 依赖处理](https://electron-vite.org/guide/dependency-handling)、[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)、[Tailwind Vite 接入](https://tailwindcss.com/docs/installation/using-vite)。实际行为以锁文件、构建及测试为证。

## 本地图标与保存基线

初始化与全部同期 Wiki 已提交本地 `7c5a2eb`，未推送。当前增量以该提交为同步基线，不能在新增改动提交后改用 HEAD 绕过差异检查。

自有图标源为 `apps/desktop/resources/icon.svg`（橙色单据与趋势箭头，不含第三方商标）。`pnpm icons:generate` 通过固定 Electron 离屏渲染生成 1024 PNG、包含 16～1024 尺寸的 ICNS 与 16～256 六尺寸 ICO，并写 SHA-256 清单。`scripts/check-icons.mjs` 在根 build 前核对源文件和所有二进制 hash、PNG 尺寸和平台头；改 SVG 而不重建会阻断构建。原图及生成资源属于产品资源，安装包依然不入库。

Main 用 nativeImage 读取 PNG，设置开发版 macOS Dock 与 BrowserWindow 图标；图像为空时启动失败，避免静默退回 Electron 标记。mac/windows builder 指定 ICNS/ICO，PNG 随 app.asar 打包且运行路径同开发目录结构。侧栏直接用同一 SVG。修改 Main 或打包图标需要重启 pnpm dev，renderer 热更新无法更新已有主进程。

本机另外执行了 macOS arm64 未签名目录包构建，Info.plist 的 CFBundleIconFile 为 icon.icns，资源与输入 hash 一致；没有把资源核对算成实际安装、签名、公证或 Windows 验收。最终验证见 [[2026-10-21-M1布局图标与契约补齐]]。
