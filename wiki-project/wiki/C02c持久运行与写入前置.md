# C02c 持久运行与写入前置

## 本轮边界

用户选择先补齐C02c所需的持久运行与写事务依赖。本轮在644c5ed之上的独立codex/c02c-run-prerequisites中整合A01b的0f613b8，保留真实知识迁移4，再新增run迁移5；不是空迁移或跳过A前驱。知识存储服务作为依赖进入当前候选，search_knowledge与validate_quote仍未注册。没有推送、修改共同分支或替A/B签署评审。

本轮交付**公共恢复契约＋真实SQLite运行存储＋原子报价提交入口**。这不是完整C01b/C02c：生产Worker尚未调用runStore，没有新调度器、写工具调用账本、恢复IPC/UI或自动启动恢复。已有只读助手和understand/revise路径继续原行为。正式写工具必须后续绑定本轮票据/事务，再补每toolCall持久身份与旧新入口统一协调；不能直接把模型写动作交给旧commitAgent。

## 契约与可发现性

AgentRun新增必填nullable clarification：waiting_input必须有1～2000字正文，其余状态为null，error规则保持。新增严格agent.list/RunListQuery/RunListResult与DesktopClient.listAgentRuns；默认20、最多100、可按状态过滤，游标为createdAt/runId，工作区由宿主绑定。mock、preload能力门禁与测试同步；所有运行命令仍不在RuntimeCommand/Worker白名单中，列表方法只返回明确未接入，不发IPC。

列表按createdAt/runId升序分页，同时间以UUID排序。状态过滤按每页读取时生效，不是跨页状态快照；恢复发现应读无过滤列表并刷新第一页，具体操作前get读取当前事实。start同operationKey同内容返回当前快照（requestId不参与指纹），异参冲突；cancel/retry控制键独立，同键同动作/目标返回首次快照且副作用为空，get获取最新状态。completed的cancel/retry保持原完成事实；waiting_input不能retry，补充输入用新业务键。

## 内部存储接口

SqliteWorkspaceRepository.runStore()返回使用同一私有SQLite连接的AgentRunStore，不暴露连接。该内部接口返回AgentRun/有界列表及必要副作用描述，失败抛公开TradeFault；未来IPC适配层负责包装RunResult/RunListResult。本轮没有把内部副作用描述作为公共DTO。

| 方法 | 实际保证 |
|---|---|
| start | IMMEDIATE事务先写queued与outbox，再返回dispatch；重复返回当前run且不dispatch。旧成功幂等通过精确凭据核验后可投影completed，无模型调用 |
| claim | 只领取指定queued/attempt一次，生成宿主executionId，绑定workerSessionId；没有网络调用 |
| get/list | 当前工作区读取与schema/指纹校验；completed还核对实际报价/对话与原幂等凭据，损坏即报错，不自动修复或重跑 |
| waitForInput/fail | 只接受当前running票据；澄清保存可重开；失败只接收公开错误码并生成固定说明，不持久化SQL/Provider原始异常 |
| commitQuote | 核对runId/attempt/executionId/session及running，再复用旧确定性金额/修订/幂等逻辑；原子保存quote/turn/idempotency/run/outbox，返回真实committedRevisionId |
| control | 取消先落库再返回abort票据；retry仅允许状态机认可的终态，attempt加一并返回dispatch。控制记录与状态/事件同事务，失败不会返回副作用 |
| recoverOnStartup | 显式将queued/running转interrupted、清票据，不增加attempt、不派发模型；重复调用无新事件。仅允许未来宿主确认旧写Worker退出并取得独占运行权后调用；本函数不建立进程租约 |

agent_run按workspace/operationKey唯一，agent_run_control另表按workspace/controlKey唯一。运行状态正文采用schema校验JSON，内部执行身份独立列，运行列表有工作区/创建时间/ID索引。outbox复用现有表，仅记录状态、attempt和真实提交引用，不是C03公开事件订阅协议。命令含用户业务原文，遵守现有本地数据边界；不存凭据、Provider原始输出或内部推理。

## 原子提交与兼容

commitQuote在唯一连接外层IMMEDIATE事务内调用原TradeStore.commitAgent。better-sqlite3嵌套事务在此是savepoint，不会独立COMMIT；只有外层成功才一起提交。五个实际SQL故障点覆盖quote、turn、成功幂等、run更新和run完成outbox，验证任一步失败全部回滚。这保留了原返回TradeResult与原指纹算法，无第二套金额实现，取舍见 [[0019-运行存储前置与同连接保存点]]。

新增committedAgentRevision核对原成功结果、恰好两个evidenceIds、真实报价/turn、工作区、父版本、root、输入及持久快照内容；不是取board首行或直接信任evidenceIds。损坏凭据拒绝派发。understand提交时新增scenarioId当前版本复核，避免模型等待期间场景变更后错误套用新场景；revise继续拒绝过时基线。旧V1/V2/V3不改写。

迁移先验证完整1..N序列，再执行事务DDL/user_version；缺前驱、重复或未来版本均拒绝，失败DDL与版本回滚。版本4沿用A的实际DDL，版本5新增run/control。真实v3场景、商品、报价、对话、幂等与事件升级后逐字节不变。此候选开启后数据库到v5；旧v3/v4应用拒绝打开属预期，回退应用须保留数据并使用兼容修复，不能删除表或降user_version。

整合时另修正A01b已发布版本异键重发的hash校验顺序：published也先核对sourceHash，防止错误hash被当作成功重放。原暂存/发布内容、人工门禁和不可变触发器保持，测试覆盖此回归；没有新增知识UI或模型知识工具。
