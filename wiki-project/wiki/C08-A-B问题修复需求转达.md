# C08 A 与 B 问题修复需求转达

负责人 C。以下内容是针对当前 `codex/m1-abc-integration` 集成分支的正式交接要求。目标不是重新分配已经完成的工作，而是关闭当前仍影响 MVP 收口的两个问题，并更新真实证据。

## 目标

关闭 A 来源资料收口与 B 拟议条款 pending 契约两个当前阻断项，并为 C 后续非作者复验提供固定 SHA、生产反例和可追溯 Wiki 证据。

## 范围

- A：大目录隔离结果、服装原始快照、有效期、认证和供应商证据，以及对应来源清单和历史诊断口径。
- B：付款/交期确认状态、公共契约、报价计算路径、版本链、重开和客户回复边界。
- 不包含正式审批、邮件外发、PDF、Windows、签名安装包或真实供应商业务签认。

## 当前共同基线

- 当前集成分支：`codex/m1-abc-integration`。
- 该分支是项目唯一集成主分支和后续人工验收基线；A/B/C 的所有最终交付必须合入此分支。
- 当前已确认的自动化结果：macOS 构建、工程门禁、Wiki 回归、单元测试和 Electron 回归已通过。
- 当前仍不能宣布完整收口：A 来源证据边界未全部关闭；B 拟议条款 pending 语义仍有生产路径缺口；正式审批、邮件外发、PDF、Windows 和签名安装包仍未验收。
- `manualAcceptance.ready=true` 只表示可以进入人工 MVP 验收，不表示 A/B/C 所有业务问题已经解决。

## A 任务：来源资料与大目录收口

### 必须完成

1. **确认大目录的实际接收状态**
   - 当前 `wiki-project/demo_data/catalog_converted.csv` 已采用隔离方案：目录为 285 行、82 个 SKU，原区间价/样品价 SKU `1600614614202` 不进入确定性核价目录。
   - 不得为该 SKU 猜填 MOQ、普通单价或有效阶梯价；原始截图、区间价、样品价和隔离理由必须继续保留。
   - 重新用生产 `parseCatalogCsv` 对当前交付文件验证，提供实际行数、SKU 数、issue 数、文件 SHA-256 和验证命令。
   - 若仍保留旧版 286 行/83 SKU 诊断，必须明确标注为历史反例，不能与当前交付结果混写。

2. **补齐服装来源证据边界**
   - 对两个服装 SKU 提供原始快照、版本/权属、采集时间、来源 URL、字段定位和文件哈希。
   - 如果受登录墙、访问限制或其他原因无法取得原始快照，必须保留 `not collected`/待补状态，并记录实际失败原因；不能用页面抄录、CSV 转录或登录页冒充原始快照。

3. **补齐有效期与认证依据**
   - 证明 `valid_until=2027-12-31` 是否来自供应商/页面原文；如果只是内部默认值，必须明确标注为内部默认，不得当作供应商价格有效期。
   - 对认证、证书编号、认证适用性、供应商身份及供应商有效期逐项给出来源证据或待核实状态。
   - CE 标签、页面字段或商品标题不能单独作为证书真实性或适用性证明。

4. **修正历史记录口径**
   - 更新 A 任务页、来源清单、`MANIFEST.md`、`SOURCE-PROVENANCE.md`、相关 C07 页面和验证记录，使当前目录状态与历史失败诊断分开。
   - 不删除旧失败证据；旧证据改为“历史反例/已被隔离处理”，新证据必须有新 SHA 和实际命令结果。

### A 交付标准

- 提供新的固定提交 SHA、分支名、父提交和文件白名单。
- 提供生产解析命令、退出码、行数/SKU 统计、issue 数及文件哈希。
- 明确列出仍未取得的原件、有效期、认证和供应商证据；不能用“字段已填写”代替“来源已证明”。
- 同一提交内完成受影响 Wiki、任务页、`CONTEXT.md`、`log.md` 和验证记录同步。

## B 任务：拟议付款/交期的 pending 契约修复

### 必须完成

1. **修复生产逻辑，不只补测试**
   - 当前 `calculateQuoteV1` 对付款和交期主要依赖固定未确认词匹配；`Proposed`、`Subject to supplier confirmation` 等 C07 实际拟议英文文本可能未进入 pending。
   - 任何非空付款/交期自由文本，除非经过明确的人工受控确认入口，否则必须保持 `pending_confirmation`/待确认状态。
   - 用户补充的具体条款不等于供应商确认；模型生成的具体条款也不等于供应商确认。
   - 不能通过修改客户正文、添加通用提示或只改变测试夹具来掩盖报价内部状态缺口。

2. **冻结公共契约与状态语义**
   - 明确 `blank`、`pending_confirmation`、`confirmed`、`proposed`、`missing` 等状态的来源和转换权限。
   - 复核 `classifyTermConfirmation` 与 `calculateQuoteV1` 的实际调用关系，避免契约已声明“所有非空文本默认 pending”，但生产计算仍只匹配少量词表。
   - 如需修改公共 DTO、Agent proposal、存储或调用方，必须同步所有调用方、mock 和测试；不复制第二套 DTO 绕过公共契约。

3. **覆盖真实 C07 反例**
   至少加入以下回归场景：
   - 付款：`30% deposit; 70% before dispatch`，标为用户/询盘拟议条件时进入 pending。
   - 交期：`EXW Guangzhou, China; 21 days after deposit and specification confirmation`，标为拟议/待供应商确认时进入 pending。
   - 文本包含 `proposed`、`subject to supplier confirmation` 时进入 pending。
   - 空付款/空交期仍进入 pending。
   - 明确通过人工受控入口确认的真实条款不再进入对应 pending。
   - V1→V2→V3→V4/重开后，未确认付款和交期不能消失；旧版本、检查报告和来源快照不能被回写。

4. **复核客户回复边界**
   - 客户正文不得输出内部占位词、UUID、哈希或检查 ID。
   - pending 存在时，客户正文可以使用面向客户的 `to be confirmed`，但不得把拟议条款写成供应商承诺。
   - 检查报告、内部依据和客户正文必须绑定同一报价版本。

### B 交付标准

- 提供新的固定提交 SHA、分支名、父提交和文件白名单。
- 提供生产逻辑变更说明，以及 C07 英文拟议付款/交期的实际回归输出。
- 至少提供 V1/V2/V3/重开，最好包含 V4 的版本链验证；不能只报告 3 个 marker-string 测试通过。
- 更新公共契约对应知识页、B 任务页、`CONTEXT.md`、`log.md` 和实际验证记录。
- 明确未修改的 C 负责文件；若确需改动客户回复渲染或桌面 UI，先与 C 协调并在交付白名单中列出。

## 共同禁止事项

- 不得把人工发布本地资料写成供应商真实性、认证或价格有效性审核。
- 不得把 `2027-12-31` 内部默认有效期写成供应商承诺。
- 不得猜填 MOQ、普通价、认证编号、供应商确认、付款或交期。
- 不得删除历史失败报告来制造“从未失败”的记录。
- 不得把自动化门禁通过写成正式业务签认通过。
- 不得提交 API Key、真实客户原件、运行数据库、完整未脱敏模型日志或安装包。
