# C02c 多步报价工具闭环

## C04后续的失败阶段与前置步骤纠正

[[C04失败阶段诊断与二轮收敛]]在原一次额度内进一步提示已实际读资料但核价前complete、未核价先读知识、当前candidateId正确但尚未读知识就校验，以及calculate_quote中quantity decimal格式错误。没有自动转换值或执行缺失工具，修正后仍过原schema/业务/规则/事务。未读资料虚假完成、错误/旧ID、写授权、未知字段/金额、零数量和Provider首错继续拒绝，只读路径保持。下文旧“没有候选虚假完成”当前须按是否已实际读取区分，不能把complete当保存成功。

协调器可注入枚举FailureObserver供C04记录阶段/白名单工具/校验分类，不改公共AgentRun或迁移。观察器异常隔离，普通报价没有新增诊断持久数据；原工具步骤和成功事务仍是保存事实来源，反馈不是授权凭据。八项合成重建只证明本地机制，旧真实报告不反填；范围见[[C04-失败阶段证据与八项回归]]。

本轮从4c09785建立独立codex/c02c-multistep-tools，未推送/合并。开工fetch得到A01b=0f613b8、B00=4e8c663、共同分支56c909e；中途复核A更新至c6539e8，已fetch确认仅合并共同分支文档/产品演示，packages源码/契约/迁移与0f613b8相同，无新业务依赖；未将无关演示工程并入任务。当前A实际最新c6539e8，PR共同祖先be53b98。A真实stage/publish/query存储及迁移4已由前置67c69c7整合，当前B仍仅有knowledge/check/run公共契约，没有已交付B01规则服务或B00a通用业务Wiki检索。依赖证据见raw/c02c-multistep-dependencies.json。

为接通用户授权的完整报价工具链，本轮补齐符合既有QuoteCheckService的真实纯规则实现quoteCheckService；原checks.ts/knowledge.ts与B远端逐字节相同，不另复制DTO、虚构B签字或把B01整体标done。B仍需复核规则语义及后续独立quote.check持久服务/双反馈UI，A需复核迁移7。当前search_knowledge是A实际已发布适用规则/原文查询，不是尚未实现的全文/向量/通用SOP检索。整个规则范围是公开B00的两类、两种条件与payment/delivery两个字段，不能宣传为完整平台/法律合规认证。

本轮实现的是C02c在上述真实公开契约内的**多步报价闭环**：读→核价→规则校验→修正候选→再校验→持久草稿写入。当前C02c工具链可运行；完整业务Wiki、B01独立报告业务、C03事件、审批/输出与真实供应商评估仍属各自未完成任务。实现验证任务[[C02c-多步报价工具闭环]]，关键取舍[[0021-多步候选授权与规则校验]]，前置[[C02c统一运行与写账本]]。

## 使用与兼容

正式“资料与报价”询盘区勾选“多步工具报价（读取、核价、规则校验后保存）”，再点击现有理解保存V1或修改保存Vn。旧单次模式默认保留；同一输入切换模式改变业务指纹并使用独立操作键。API在既有understand/revise payload中增加可选executionMode:tool_loop，agent.start复用同一payload，无新workspace、报价金额或执行票据入口；旧命令/旧成功幂等原格式兼容。

多步命令仍进入唯一AgentRunCoordinator、同一Worker独占生命周期与取消/显式retry。每个run最多保存一版未审核草稿；两轮修订分别新建用户操作，旧V1/V2/V3不改。一次run可以多次核价与校验修正候选，但不会在内部产生多个已保存版本。旧独立“只读助手”继续四工具只读，ReadToolRuntime包装器拒绝注册写工具。

当前B00每次只能表达一个规则品类，多步候选的实际商品须只有一个category。平台/市场取冻结场景，规则品类取真实已读取商品的唯一category，不要求场景描述标签等于CSV品类字符串，也不推断别名。C仅给B00校验输入建立该category视图，不改实际保存的场景/快照。服装、板材、紧固件等任意品类均可，不同单位不换算，未定价保持null；混合实际品类需拆任务，不能拿部分覆盖作全部通过。旧手工/单次行为保持。

## 宿主工具与允许流程

| 工具 | 真实能力与约束 |
|---|---|
| search_catalog / get_product_revisions | 复用CatalogQuoteReadAgent.prepare的真实已发布商品快照与来源；understand的候选商品必须实际读取过 |
| get_quote | 仅授权本次revise命令的精确baseId；保留历史快照与最新性事实，不允许模型读取其他报价 |
| calculate_quote | 输入Understanding或RevisionProposal，复用calculateQuoteV1/reviseQuote，不接受单价/合计/审批字段；返回candidateId及无持久报价身份的核价预览 |
| search_knowledge | 宿主从冻结场景绑定platform/market，从已核价商品绑定唯一实际category及当前时间，调用A的knowledge.query；返回真实published版本、原文/hash/定位，验证UTF-8 hash且最多50版本 |
| validate_quote | 只接受当前candidateId，必须已读取适用知识；实际纯规则计算并返回独立validationId、来源绑定报告和allowed；模型不能提交“已通过”报告 |
| create_draft / apply_patch | 按本次understand/revise只注册其一，仅接受本run当前candidateId+validationId；经宿主票据、再校验与账本提交一版draft，成功立即结束run |

允许在校验发现问题后按用户已明确的事实重新calculate_quote、search_knowledge/validate_quote，再写入；新核价或重新检索使旧validationId失效。模型不能利用旧候选、其他run的ID或直接带价格的proposal绕过检查。未注册工具/权限错误/真实工具失败终止后续请求；合法的阻断校验报告可作为修正依据，若直接请求保存仍报RULE_BLOCKED且不写报价。参数错误默认结束；C04后续只对缺失/类型错误提供一次受限纠正，规则见下节。缺事实用clarification持久waiting_input，旧输入不能自动retry。

ToolLoopRuntime共用既有JSON动作核，不是Provider原生tool_calls SDK。每run最多12工具、120秒、100000 UTF-8上下文字节；预算耗尽后不再发第13次模型请求，取消/旧session/旧attempt在每次模型与工具边界复核。宿主同步调用多步135秒等待，原单次60秒、只读135秒保持。来源与模型结果均为不可信数据，不能改变宿主工具集和权限。complete不能伪造保存成功；成功写入后不再请求模型生成“完成”文本，最终引用来自SQLite真实committedRevisionId。

## 两类规则的实际语义

quoteCheckService是无Node/SQLite/模型依赖的纯领域实现，输入公开QuoteCheckInput，输出严格CheckReport。执行前重新核对发布时点、scope（大小写/别名不隐式转换）和每文档最新匹配版本。纯接口按B00读取quote.scenario.category；C的checkDraft在校验视图把该字段映射为商品实际品类，报告ID/版本仍绑定真实原快照，保存数据不改。required用trim判空；forbidden_literal用NFKC+toLowerCase后字面子串比较，不执行动态JS/SQL/正则、不推断付款比例或法律意义。

每个问题checkId固定由quote revisionId、knowledge revisionId和ruleId构成；缺覆盖按revision/category固定ID。两类coverage始终出现，无适用规则产生pending和无虚构来源批注。问题保留字段、severity、来源版本/hash、合成标记和UTF-16定位。warning/pending允许保存未经审核草稿并显示待确认；block禁止保存。金额未知与费用未核定不填零，不把“执行了规则”改成“已批准”。QuoteSnapshot.pending沿用基础业务模块的缺项与合成说明；新报告仅说明B00有限规则执行，不抹去通用业务风险提示。

## 写事务与迁移7

候选、validationId与完整读结果留在当前尝试内存，不能跨重启当作可恢复授权。公开AgentRun新增可选toolSteps与validation（calculation_preview或saved_revision）；旧JSON没有默认字段重写。步骤含宿主toolCallId、attempt、连续ordinal、真实工具名/ok/公开错误码与evidenceIds，不存凭据、Provider原始输出或内部推理。UI显示中文步骤名称与预览/已保存检查状态；问题带来源/hash/定位和合成标识。

迁移7保留1～6原DDL，为agent_write_call加nullable validation_json，并新增不可更新/删除的agent_tool_step。当前attempt步骤投影在run中，历史attempt步骤独立永久保留；显式retry清空当前投影/候选报告，新attempt重新读取/核价/校验。读步骤短事务落盘，但恢复只标interrupted，不自动重放模型或后续写动作。旧v6报价、run/control/回执既有列与JSON字节升级后保持；新增列为null，不伪造旧校验报告。

prepareValidatedWrite在副作用前保存原参数与宿主核价授权。commitValidatedWrite同连接外层IMMEDIATE事务内：复核当前ticket→核价日期未跨UTC日→重读最新场景/报价与商品→复用确定性算法比对完整候选业务内容→重新查询当前已发布适用知识/hash指纹→重算规则并拒绝block→写报价/turn/成功幂等/run/outbox/committed回执→比对实际保存与核价内容→生成绑定真实revision的检查报告与成功写步骤。任一SQL或报告/步骤保存失败共同回滚；之前prepared保留，失败/取消/恢复后abandoned。提交期间不await模型/网络。

知识更新、当前报价已有新版本、场景/商品变化或核价日期变化都会拒绝旧授权，不后台重新收费。重开/查询completed时进一步核验步骤投影与不可变步骤表、报告/报价/原知识及回执证明，损坏报STORAGE_ERROR，不信任伪造“通过”。旧成功幂等可回读原版本，重复调用不重写报告或再调模型。数据库v7不由旧v6程序打开；回退须兼容构建或向前修复，不删除表/降版本。
