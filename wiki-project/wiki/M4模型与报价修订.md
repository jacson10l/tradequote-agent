# M4模型与报价修订

正式应用现支持 DeepSeek 设置→询盘结构化理解→受限业务命令保存 V1→两轮自然语言修改→V2/V3→字段/金额差异→重开。网络 adapter、主/业务进程、SQLite 和 UI 均实际运行；本轮自动验收使用本地 HTTP 替身与合成资料，未调用真实账户，不代表 DeepSeek 业务效果或完整参赛要求已通过。T40/T41/T42/T31 仅下述切片完成，T00 人工评审不代签。

## 使用与演示

启动 `pnpm dev`，进入“模型设置”，填写 API Key 和账户可用的模型 ID，保存后点击“测试已保存的连接”。测试仅发送合成 JSON，成功状态仅在本次会话保留；不是自动审核业务内容。模型 ID 可配置，页面例子不是账户可用型号保证；当前没有迁入 M0 的模型列表发现，不读取/迁移 M0 凭据。

在“资料与报价”保存可编辑场景、发布合成 CSV。填客户和中文询盘，例如“请提供100件 DEMO-TEE 报价，付款和交期待确认”，点击“理解询盘并保存 V1”。第一轮“数量改为120件”保存 V2；第二轮“付款改为30%预付、70%发货前付清，确认后30天交货”保存 V3。可用任意已发布品类；该样本仅帮助重复演练。示例的确定性金额为 900.00→1080.00→1080.00 USD，均不含运税费。

历史选择器可查看同一单据的各版本，差异默认与父版本比较，也可选择更早版本。数量/条款、档位/单价/行金额/合计、待确认原因分别标明变化类型；不依赖模型 summary 推测保存成功。界面只有收到已提交快照才显示“已保存为 Vn”。历史版本禁止继续修改，冲突要求重新加载并选择最新版本。对话记录含用户要求、模型建议、模型 ID、时间、对应版本；模型建议不是已审批事实。差异表保留最小列宽并横向滚动，不把长条款压成窄字列。

## 正式设置与密钥边界

`model.status/save/clear/test` 是主进程白名单入口，均验证窗口、主 frame、URL、method 与 strict 字段；renderer 不获得通用 IPC、文件路径或解密接口。Key 仅在保存请求及主进程内存中使用；返回 hasKey/model/storage/verifiedAt，没有 Key。safeStorage 可用且 Linux 非 basic_text 时写 userData/model-settings/credentials.enc，同目录临时文件→rename，mode 0600；否则明确 memory 并删除旧磁盘记录。空 Key 保留当前内存已配 Key；解密失败保留旧文件并报错，仅显式重新保存/清除替换它。设置操作串行，连接测试期间不接受另一设置写入。

主进程仅在 Agent 请求时把凭据快照放入内部 WorkerRequest，renderer 命令 schema 不接受 credentials。业务数据库、对话与 Wiki 不存 Key；没有认证头、原始响应或异常全文日志。清除设置不取消已经发往服务的请求；本轮无运行取消入口。safeStorage 的签名/升级迁移与 Windows 行为仍须实际验收。

## Provider、上下文与允许操作

正式端点固定 https://api.deepseek.com/chat/completions；使用 JSON 输出、明确 JSON 指令和例子、非流式、max_tokens=4096、关闭 thinking、45 秒 deadline、拒绝重定向及大于128 KiB响应。仅接受 finish_reason=stop、无 tool_calls 的完整 JSON，空/截断/非 JSON/字段注入拒绝；401/403、429、超时分别映射公共错误码，其他网络错误不回显供应商全文。不自动重试模型收费请求。Main 对 Agent 的传输等待为60秒，普通业务仍15秒；传输结果未知可用相同操作标识重试或重新读取报价。

产品允许模型理解商品 ID、正数 decimal 数量、匹配单位及明确条款；缺事实/歧义要求 clarification，不默认补齐。修订只开放 setQuantity(productId,quantity)、setPayment(value)、setDelivery(value)，每批1～50项且同字段不能重复。商品必须属于当前快照，数量不允许0、不换单位；拒绝价格、金额、审批、增删商品等字段。业务服务重新计算价格档位、行舍入与合计，缺价格/过期继续未知。全部新版本为 draft，无发布/审批/导出能力。文本指令遵从性仍需真实模型评估，schema 不可能证明模型提取语义完全正确。

询盘理解最多50个已发布商品，上下文只包括商品标识/名称/品类/单位/描述、场景与询盘，不读取价目表金额作为模型上下文。修订发送当前事实快照及最近6条成功对话，不发送整份商品价目表。总上下文超过100000 UTF-8字节拒绝，单询盘/修改要求最多8000字符。外部资料和历史对话始终当数据；无 shell/任意网络/数据库工具。用户在输入文本中主动提供的商业内容仍会随请求发往供应商，页面明示。

仅为桌面测试提供环回 HTTP fixture：Main 必须同时满足未打包、有 TRADEQUOTE_TEST_DATA、URL精确匹配127.0.0.1数字端口；生产包忽略该变量，不能由 IPC 改端点。正式应用不会自动切换到假模型或伪成功。当前 HTTP 替身验证覆盖完整 adapter/进程/持久化，不替代真实供应商能力矩阵。

## 版本与事务

迁移3追加 quote_revision、agent_turn 与不可变触发器，不改迁移1/2和历史 quote_v1 字节。V1.id 是 rootId；V2+ 有独立 id、rootId、parentId、递增 version，沿用单据号、场景/商品/来源快照与计算策略。新版本按当前日期重新核对原价目表有效期。UNIQUE(root_id,version)/parent_id 防分叉；快照 JSON 的 SHA-256 单独存储，UPDATE/DELETE 被拒绝。

模型调用在事务外异步运行，worker 可处理其他查询；返回后 IMMEDIATE 事务再次验证 baseId/expectedVersion 是当前头，understand 再校验场景ID。版本、对话、outbox、幂等结果同事务提交；任一失败全部回滚。并发导致旧基线时拒绝，不把旧建议套到新版本。对话 summary 不参与金额决定。

Agent 幂等按 method/payload/固定 agent_tool 来源计算；requestId 与 Key 不进入 hash。已提交结果在调用模型前回放，重开也可用相同 idempotencyKey 回放；同 key 异内容拒绝。进程内最多两个模型请求，相同key的并发请求共用 promise。UI 在页面生命周期保留各操作键；未提交表单、失败/澄清对话和待决运行目前不持久化，应用重启后需先查版本再发新请求，不能宣称 T44 恢复已完成。
