# 黑客松演示封板目标与ABC分工

## 目标

当前最高优先级是封板一个能在演示机上连续运行、可重置、可解释的业务闭环：

1. 询盘 → 询盘理解/必要澄清 → 报价 V1 → 两类规则检查；
2. 生成带依据和风险标记的英德客户回复草稿，并明确“未审核”；
3. 买家变更 → 报价 V2/V3 → 差异 → 再次检查。

演示闭环优先于完整知识维护、正式审批、PDF 导出和双平台验收。维护入口保持关闭，未完成能力必须在演示脚本和界面中如实标识。

## 背景

当前正式工作台已经具备 CSV 导入、手工报价 V1、保存/重开及受限 V2/V3 能力；参赛演示仍缺连续的规则反馈与客户可见产出。完整边界见 [[M2真实报价V1]]、[[M4模型与报价修订]]。

## 封板验收

- 使用冻结的主演示样本，能从空工作区按脚本完成两条流程；
- V1、V2、V3 的金额、币种、阶梯价和差异来自确定性业务模块；未知值不得当作零；
- 正常规则案例与“违规 → 校正”案例各至少一条，风险标记和文本批注可见；
- 英语和德语回复均为可读草稿，显示依据/风险并标明未审核，不宣称已审批或正式发送；
- 应用重开或演示重置后可重复运行，失败步骤有明确恢复动作；
- 真实命令、退出码、环境和未完成项记录在 Wiki/raw，不能用 HTML 样机或浏览器结果代替 Electron 验证。

## 三人分工

### A：资料冻结与来源边界

- 冻结主演示 CSV、规则所需资料和 MANIFEST，确认 SKU、单位、币种、梯度和合成来源；
- 提供可重置的演示数据包及实际导入/发布验证；
- 维护修复继续按 B 政策推进，但不阻塞本轮演示；维护入口仍保持关闭；
- 交付固定 SHA、Wiki/任务页、验证命令和剩余风险。

### B：规则案例与客户产出

- 冻结一个正常报价案例和一个违规后校正案例，规则结果必须能在 UI 中解释；
- 冻结最小英语/德语客户回复草稿，包含报价摘要、条件、风险和“未审核”状态；
- 不把合成规则、模型推断或未裁决资料写成真实供应商事实；
- 交付固定案例输入/输出、契约边界和实际验证记录。

### C：桌面串联与彩排

- 固定演示启动、重置和失败恢复步骤；
- 在真实 Electron 工作台完成两条流程的端到端彩排，记录 V1/V2/V3、规则反馈、双语草稿和重开行为；
- 维护接线只有在 A 按 B 政策完成并由 C 复验后再恢复；不让维护缺口阻塞演示闭环；
- 交付演示脚本、备用路径、实际 Electron 证据和已知限制。

## 替代方案

完整知识维护、正式审批、PDF 和双平台验收继续按原任务推进，但不再作为今晚演示的入口条件。

## 回滚方式

若任一演示环节无法在真实 Electron 中稳定复现，保留已验证的 V1 保存/重开路径，展示明确的未完成状态，并将失败证据写入本任务。

## 后果

本决策会把完整维护和正式发布排到演示封板之后；所有未完成能力必须继续在状态和演示说明中标识，不得把合成数据或浏览器样机写成正式交付。

## 优先级规则

演示闭环中的阻断优先修复；不影响演示闭环的维护、审批、PDF、Windows 和完整迁移工作排到封板之后。任何新增改动仍必须同步受影响 Wiki、任务页、日志和验证证据。
