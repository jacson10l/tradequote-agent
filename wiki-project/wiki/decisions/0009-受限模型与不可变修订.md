# 0009-受限模型与不可变修订

## 背景

用户要求正式 DeepSeek 设置、询盘理解和两轮修改，保存V2/V3展示差异。现有 quote_v1 已有不可变数据，完整九类 typedPatch 与审批契约仍为规划基础，不能无迁移改写旧快照。

## 决定

正式工程使用有界 JSON Provider，模型只提交结构化理解或三类受限建议，由业务服务检查并确定性计算；Agent 不直接拥有 SQLite、场景发布或审批能力。此次 agent.ts 的 RevisionPatch 是实际支持的产品子集；不把尚未实现的九类 patchToolJsonSchema 宣告可执行。待完整业务查询/价格版本/包装落地后通过新增契约版本迁移，不默默放大当前权限。

保留 V1 表，迁移3单独追加修订与对话；每轮带 baseId/expectedVersion，模型调用结束后再次检查当前头，原子写版本/对话/审计/幂等。原价目表快照继续用于新版本，当前有效期重新核对；不会静默切换商品价格来源。Main 用 safeStorage 管理凭据，按请求送入 worker，renderer只看脱敏状态。

## 替代方案

直接让模型产生完整报价 JSON 会允许覆盖金额/来源；改写 V1.version 会破坏历史不可变保证。此轮直接接完整工具循环会引入尚不存在的检索、审批与恢复语义，故先采用单次结构化建议→受限服务调用。只做聊天文本不具备真实 V2/V3，不满足本次要求。

## 后果

支持商品数量、付款和交货要求两轮修改，暂不支持增删行、改价、换币、包装策略、完整运行事件与取消。自动验证使用 HTTP 替身，真实 DeepSeek 语义、Windows safeStorage 和发布身份验收仍未完成。无语言产出/文化规则服务，不能提前关闭赛事 C-03～C-06。

## 回滚方式

不降级或删除已存在的迁移3数据；旧程序会按 user_version 拒绝打开新版数据库。需要回滚版本时先备份，在新版代码保留迁移与读取能力的前提下关闭新入口；数据迁移必须另行设计并验证，不修改原 quote_v1。
