# 0012 C01a 取消与提交边界

## 背景

B00 已推送待评审合入；run 持久化还需 A 的迁移4先行与迁移5复核。C 可以先实现状态规则和网络取消，不能复制待合入 DTO 或提前宣称正式恢复接口可用。现有报价提交是单 worker 同步 SQLite 事务。

## 决定

复用已在共同基线的 RunStatusSchema 编写纯状态转换，通过 domain 公共出口提供。进程内取消按业务 operationKey 共享 controller，Provider 接受可选 AbortSignal；模型返回后再次检查取消，进入同步提交前关闭取消窗口。完成事实优先于迟到的取消，模型收费请求只由 execute 的显式调用启动。

正式 start/get/cancel/retry、run 表、attempt 和重启恢复留到 B00 合入及迁移协调后。现阶段 cancel 的 boolean 只表示本进程是否接受取消，不是正式 RunResult，不表示数据库中没有报价。ADR 编号避开 B00 的0010及 A 分支已存在的0011。

## 替代方案

只 abort fetch 无法拦住忽略信号的晚到输出；只在 UI 隐藏加载状态无法阻止保存。复制 B00 DTO 或现在另开数据库会破坏统一契约和原子提交要求。将旧 understand/revise 改成立即返回 queued 会破坏兼容性。

## 后果

可先独立验收取消安全边界和旧桌面回归。当前安全性依赖同步提交中没有 await、没有第二个写 worker；后续接 run 时仍必须在同一事务写运行终态和报价引用，不能把进程内控制器当作崩溃恢复。真实模型、Windows与实际 run 强杀恢复维持待验收。

## 回滚方式

取消内部 cancel 原语和 Provider 的可选信号即可恢复旧执行路径；本切片未新增迁移、修改旧快照或开放新 IPC。删除纯状态模块时同步 domain 导出、测试和 Wiki 映射，不删除本轮验证证据。
