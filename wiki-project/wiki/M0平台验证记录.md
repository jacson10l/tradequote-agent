## 最终选择与版本范围

本轮选择 **Electron 44.9.2＋electron-builder 26.15.3＋最小执行器**；Harness 移为开发期候选，不进入生产依赖。支持版本指纹过窄的 preview runtime 不作为桌面核心前提，不为它直接降级 Electron。详见 [[0004-M0平台与执行器选型]]。

保留 better-sqlite3 13.0.3、Drizzle 0.45.4、ExcelJS 4.4.0、csv-parse 7.0.3、Mammoth 1.13.0＋fast-xml-parser 5.11.2 / JSZip 3.10.2 位置适配、PDF.js 6.4.299。选用 printToPDF；react-pdf 4.9.0 仅作对照，没有必要额外引入另一套模板系统。字体包为 Noto Sans 5.3.0、SC 5.3.1、Arabic 5.3.0，SIL OFL，许可随包保留。精确依赖树见锁文件；这不是未经 Windows/真实模型验证的全平台冻结声明。

## 发现并修复的问题

- 首次 tsc 缺 Node 类型：显式加入 @types/node 与 types 配置。
- 禁用页面脚本后仍尝试 executeJavaScript 等字体：移除注入，使用页面加载/Chromium 打印链路和字体嵌入结果验证。
- PDF.js 在 Utility Process 需要显式 workerSrc，6.x 文档代理不再提供 destroy：配置 worker 路径并销毁 loading task。
- 加强表头断言时误把纯页脚末页也要求为表格页：改为逐页判断是否含数据行，所有含表格行的页面仍严格检查重复表头。
- Harness 原生 runtime 指纹不兼容：保留首次失败 JSON，切换最小执行器。
- 初次生产依赖包含 Harness 时，builder 的 pnpm 依赖枚举 OOM：保留 [构建失败摘要](../../experiments/m0-platform/evidence/package-initial.json)，移至 devDependencies 后重新构建。该现象不证明所有 OOM 都由 Harness 单独导致。
