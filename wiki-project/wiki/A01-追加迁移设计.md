# A01-追加迁移设计

本页说明统一目标 schema、追加步骤顺序/编号与执行身份、识别与拒绝位置，以及事务/回滚/重开要求。逐谱系接受预期与失败注入见 [[A01-迁移验证计划]]，支持/拒绝判定见 [[A01-迁移谱系支持与拒绝矩阵]]。

## 识别与拒绝位置

- 只读识别 `identify(db)`：先 `snapshotSchema` 读取 sqlite_master 与 user_version（不写），再 `identifyLineage` 做对象级能力判定（必要列、索引 `UNIQUE`/`partial`、触发器 `RAISE`），随后 `verifyLegacyLedger` 核对旧 B 账本 hash 与登记能力存在性（N11），再 `verifyRegistryLedger` 核对新账本 hash 与登记能力存在性（N10）。全部只读。
- 构造器预检 `preflightMigration(file)`（index.ts）：文件存在则以 `new Database(file, { readonly: true })` 打开并 `identify`；文件不存在视为全新直接进入写开。**拒绝发生在只读预检，早于任何读写真开**，因此「拒绝不修改 DB」明确覆盖打开动作：不创建 -wal/-shm、不写 user_version、不建账本。
- 拒绝抛 `MigrationLineageError`，消息 `MIGRATION_LINEAGE_REJECTED:<lineage>`；lineage 为 mixed/tampered/unknown 之一。

## 统一目标 schema

统一库同时具备九个能力切片、user_version=8（8 不与任何历史谱系编号冲突）。追加按 `MIGRATION_STEPS` 顺序执行，编号保留各谱系原始编号，不重排：

1. common:1（workspace/source/job/idempotency/outbox）
2. common:2（scenario_revision/catalog_batch/catalog_product/quote_v1 + 不可变触发器）
3. common:3（quote_revision/agent_turn + 不可变触发器）
4. common:4（knowledge_revision + 索引 + 不可变触发器，A01b）
5. c-run:5（agent_run/agent_run_control + 索引，C）
6. c-run:6（agent_write_call + 索引 + 不可变触发器，C）
7. c-run:7（ALTER agent_write_call 加 validation_json + agent_tool_step + 不可变触发器，C）
8. knowledge-wiki:6（knowledge_source/knowledge_wiki/knowledge_lifecycle/knowledge_consumption + 索引 + 不可变触发器，A01c）
9. check-report:7（quote_check_report + 索引 + 3 触发器，B）

依赖：common 1~4 是共同底座；c-run6/7 依赖 c-run5；knowledge-wiki:6 只依赖 common；check-report:7 依赖 quote_v1（common:2）与 quote_revision（common:3）。knowledge-wiki 与 check-report 相互独立，但统一顺序固定为 knowledge-wiki 在前、check-report 在后。

## 执行身份与账本

- 每步 `lineage` 记录执行身份：common 为 A/B/C 共同，c-run 为 C，knowledge-wiki 为 A，check-report 为 B。
- 新账本 `migration_registry(lineage TEXT, version INTEGER, sql_hash TEXT, applied_at TEXT, PRIMARY KEY(lineage, version))`，以 (lineage,version) 为主键，区分 C6 与 A6、C7 与 B7；sql_hash = sha256(CRLF→LF 归一后 SQL)，与 C/B 固定诊断一致。
- 旧 B `schema_migration` 表不删不改，`verifyLegacyLedger` 交叉核对 hash 与登记能力存在性（N11），不符判 tampered 拒绝。
- 新账本在只读预检由 `verifyRegistryLedger` 交叉核对 hash 与登记能力存在性（N10），拒绝早于读写真开，不产生 -wal/-shm。

## migrate 事务与回滚/重开

- `migrate(db)`：先 `identify` 通过（可升级且账本一致），再单连接、单 `.immediate()` 事务：建账本表 → 已存在能力补记账本/核对指纹 → 缺失能力按序 `exec` 并记账本 → 置 `user_version=8`。
- 任一步失败（含注入的坏 SQL、账本 hash 不符）整体回滚：不部分建表、不伪记已执行、user_version 不变。
- 重开安全：升级是幂等追加，已存在能力只核对不重建；失败后重试从原谱系重新识别并续追，不产生半成品。

## 责任分工

- A（本任务）：维护迁移顺序/识别/账本/拒绝边界与 `migration-lineage.ts`、`migrations.ts`、`index.ts` 预检。
- B：按谱系账本适配接口/报告/消费，提供事务证据。
- C：在独立组合 worktree 验证全矩阵后接桌面，跑 macOS 全量验收。
