# MVP 范围与验收

目标是可重复演示的跨品类询报价桌面应用，并为三名开发者持续迭代建立清楚的边界。参赛六项要求、纠错与证据标准以 [[参赛要求对齐与验收]] 为准；产品能力尚未完成。按功能完成与验收推进，不用固定工期压缩目标。当前手工 V1 进展见 [[M2真实报价V1]]；[M0 技术验证记录](技术验证记录.md) 为历史探针，不等于完整应用验收。

## 已确认决策

| 项目 | 决策 |
|---|---|
| 产品形态 | Electron＋React＋TypeScript；macOS 和 Windows 均实际安装、运行核心流程 |
| 首版部署 | 单机、本地业务数据库，无共享服务器；本机切换岗位演示，不宣称真实多用户隔离 |
| 模型 | 允许联网调用；优先 DeepSeek，地址、模型名和凭据可配置；模型适配与 Harness 选型分开 |
| 上游复用 | 优先检查 Solivio 和 DeepSeek Harness，允许依据验证结果替换 |
| 商品范围 | 跨品类，不把 T 恤、固定市场或固定材料写进通用业务代码 |
| 资料 | 用户导入 Excel/CSV、文字型 PDF/Word 和业务配置；提取结果确认后生效 |
| 操作方式 | 单据工作台为主，Agent 对话辅助；修改同步到单据并显示差异 |
| 自动化边界 | Agent 自动保存新草稿版本；缺项、歧义时确认；人工最终审核 |
| 定价 | 销售价目表与成本核价均支持；计算由业务代码完成，保存依据 |
| 语言 | 中文界面、内部摘要和任务；支持用户指定任意目标语言，模板、术语独立配置 |
| UI | 浅色工作台；最新选择为 `getdesign add mistral.ai`，替代 Claude |
| 协作 | 三人按模块负责前后端闭环，先确定公共接口与数据契约 |

## 首版业务闭环

资料导入 → 提取与映射 → 人工确认入库 → 输入询盘 → 检索商品与知识 → 确认关键缺项 → 确定性核价 → 生成报价 V1 → 对话修改 V2、V3 → 核对差异与内部任务 → 生成目标语言产出草稿并检查 → 人工审核指定版本与产出 → 导出对应版本的正文和 PDF。

两条工作流分别验收：①询盘到可审核报价；②买家变更到新版本、风险说明和采购/审核任务。RFQ 简短回复与正式邮件报价使用独立内容结构，不能只换标题。

## P0 功能与验收编号

| 编号 | 功能 | 必须观察到的结果 |
|---|---|---|
| AC-01 | 文件导入与确认 | CSV、XLSX、文字型 PDF、DOCX 均有固定样本；预览字段、单位、币种、原位置；用户确认前不改变已发布业务数据 |
| AC-02 | 导入纠错 | 缺列、乱码、未知单位、重复记录、冲突价格可定位并修正；重复提交不重复入库；纯扫描件提示需转换，不伪造抽取成功 |
| AC-03 | 跨品类建模 | 同一应用导入服装、按面积计价板材、按重量计价紧固件三组样本；使用不同属性与单位，无品类代码分支；新增属性通过配置完成 |
| AC-04 | 询盘理解 | 粘贴中文或目标语言询盘，抽取结构化需求并保留原文引用；关键缺项以问题/任务出现，不自动替换商品 |
| AC-05 | 两种定价 | 价目表、数量档位、成本与目标毛利模式均可算；币种转换、折扣、费用和舍入符合契约；缺项显示未知，不当作零 |
| AC-06 | 知识可追溯 | 商品事实、价格、规则、术语可回到已发布版本与来源位置；冲突和过期来源可见；检索失败与无结果区分 |
| AC-07 | 两类检查与两种反馈 | 合同条款与资料支持的目标市场规则分别检查，平台规则另纳入 AC-17；每类至少一例问题及处理结果。同一 checkId 同时提供可定位的风险标记＋文本批注（原因、依据、建议），修正后重检；通过、提醒、阻断、待核实、不适用分别显示，不声称全面合规 |
| AC-08 | 自动草稿修订 | 对话更新后保存 V2、V3；展示变更前后、原因、重新计算项；旧版本内容不变；恢复历史会新建版本 |
| AC-09 | 内部任务 | 包装费用/交期等未知项形成中文任务，含字段、证据和负责岗位；解决任务后重新核算/检查，不直接批准报价 |
| AC-10 | 任意语言辅助输出 | 可输入/选择目标语言；首批参赛实测英语、德语，中文输入后生成业务产出；金额、SKU、规格、日期来自同一快照；生成失败明确提示。通用模板回退要标识，不能据此声称通过特定平台/文化适配 |
| AC-11 | 审核与导出 | 人工审核绑定当前版本与对外产出；关键未知项/阻断项未解决不能定稿；草稿 PDF 显著标记；下载不自动标记已发送 |
| AC-12 | 运行可恢复 | 模型超时、取消、应用退出、PDF 失败后已提交版本保留；重试不重复写入；展示真实调用状态 |
| AC-13 | 本地维护 | 支持独立演示工作区、备份与恢复；重置演示数据不影响其他工作区；API Key 不出现在导出包或日志 |
| AC-14 | 双平台 | macOS 和 Windows 上安装包均能完成导入→V1→V2→V3→审核→PDF→重启读回 |
| AC-15 | 桌面交互 | 单据始终可读；对话结果定位到字段；空态、错误、禁用、焦点、窗口缩放可用；不能只展示聊天或静态页面 |
| AC-16 | 三人协作基础 | 契约、迁移、锁文件、模块边界、CI、关键测试和开工说明齐备；新成员按 README 可重建 |
| AC-17 | 平台与文化适配 | 选定一个业务平台，规则/风格/locale/术语配置可追溯；RFQ 与邮件结构有实质区别；英德商务语气、称呼、日期/单位及限定条件经人工复核；违规、直译式表达、无依据承诺、来源失效样例得到反馈；事实不随本地化改变 |

AC-03 的三个品类是建议的验收样本集，不是产品允许的品类白名单。可按资料质量替换样本，但应保留件数、面积、重量等差异，证明配置扩展能力。

“任意语言”指用户可以提出任意目标语言请求，系统按模型能力辅助生成，并提供编辑、核对与错误反馈；不保证所有语言都达到专业人工译审水平。首批验证英文、德文，增加一个 CJK 和一个 RTL 样例检查字体与布局。不能把未测试语言标记为已验证。

## 页面与主操作

| 页面 | 核心动作 | 负责人 |
|---|---|---|
| 工作台 | 查看单据、待办、最近版本、创建询盘；单机角色切换有演示标识 | C 框架，B 数据与单据列表 |
| 询报价详情 | 中央单据；辅助对话；来源/风险抽屉；计算依据、版本差异、审核与输出 | B 单据，C 对话 |
| 资料中心 | 商品与价格、原件、导入映射、企业知识、规则/术语发布 | A；B 提供定价与校验配置编辑器 |
| 任务与版本 | 中文岗位任务、解决证据、历史比较、恢复为新版本 | B |
| 设置与运行 | 模型配置、连接测试、语言模板、运行失败恢复、备份、演示工作区 | C；A 提供备份存储接口 |

UI 页面可以以侧栏/标签页组织，不要求每项单独窗口。语言输出不改变已经确认的事实。源语言和目标语言分别记录。

## 明确后续范围

首版不建设共享服务器、多租户、真实组织权限、邮箱或平台连接、自动外发、自主互联网检索、扫描件 OCR、无限制脚本/插件市场、复杂物流或税务引擎、自动更新服务。常见税费、运费可作为有来源的手工费用配置参与计算，不能伪称覆盖各国自动税务核算。

Excel/Word 的首选技术映射是 XLSX/DOCX，旧版 XLS/DOC 的兼容性在 M0 记录；若没有可靠解析器，提供明确的转换提示，不能把旧格式悄悄算入验收通过范围。

自动知识更新传播、批量询盘队列、服务器共享列为后续迭代。首版仍需在检索和审核时检查来源有效期；数据失效不能显示为检查通过。

## 对原方案的调整

原方案的“固定德国 T 恤、英德限定、Fork Web 应用、2 名开发与 7～10 天”分别调整为：跨品类配置、任意目标语言、Electron 单机架构、三名全栈与里程碑验收。原两工作流、来源约束、版本快照与确定性计算保留。

2026-10-21 已取得用户提供的“参赛任务”单页截图，完整赛规仍未取得。截图要求“两种语言或两类角色/场景”，没有“至少两个电商平台”；批量生成是鼓励、多岗位输出可选。项目选英德首批实测，保留 RFQ/邮件作为业务设计；两条工作流、初稿后两轮对话、两类校验与两种反馈分别验收。详见 [[参赛要求对齐与验收]]。双平台安装、跨品类/四格式等项目要求仍保留；海报、时长与提交格式待完整规则核验。
