# 核心业务流程

当前正式链路是“场景/CSV预览→人工发布→手工报价V1→重开”，以及“模型设置→理解询盘V1→受限两轮V2/V3→历史差异”。完整目标还包含业务知识检索、规则与内部任务、语言产出、人工审批和PDF，尚未闭环。先读 [[项目说明书]] 的完整业务解释，再按 [[M2真实报价V1]]、[[M4模型与报价修订]] 核对已接通范围。

> 2026-10-21 本轮增量见 [[M0平台验证记录]] 与 [[0004-M0平台与执行器选型]]：新增真实 Electron/SQLite/解析/PDF/设置页探针；Harness 在当前 Electron 版本失败，默认切最小执行器。下文原 M0-reuse 结果保留其历史作用域。安装/双平台验收按用户决定暂缓。


历史M0-reuse可运行链路是技术验证：收集器先跑 Solivio 对照，再创建宿主环回服务、启动真实 SDK/runtime、发送合成用户输入。模拟模型依次返回检索、计算、创建草稿与重复创建调用；业务桥接将参数传回宿主。宿主以 Decimal 返回 0.30，只保留一个 revision。

随后模型请求未注册的 bash、把数量传成 number、伪造 workspaceId；验证这些调用没有进入宿主业务服务，且对应工具结果标为错误。成功输出的 JSON 由断言解析，不能替代真实模型 schema 遵从性测试。

运行正常关闭后，重建进程并恢复 session，再次请求同一操作；宿主仍存活，幂等 Map 返回旧版本。下一轮故意挂起模型响应，close 取消 runtime；检查 pending 拒绝与 OS PID 消失，再恢复会话。

提交后的版本不会被取消回滚。实验没有注入“数据库提交恰好与取消竞争”，也没有宿主崩溃；不能据此宣布生产原子性或恢复机制完成。

产品目标流程仍是“资料导入/发布→询盘→草稿→变更/采购确认→多语言产出草稿→检查与人工审核指定产出→导出”，见 [[01-MVP范围与验收]]。实际状态所有权见 [[数据持久化与状态]]，失败路径覆盖见 [[测试与验证地图]]。


## 正式手工 V1 链路

[[M2真实报价V1]] 已实现用户保存场景→选/粘贴 CSV→预览错误与来源→人工确认发布→输入客户询盘与商品数量→确定性价目表核价→事务保存 V1→重启读取。缺价格/过期/MOQ 使商品金额未知，运税费不默认零。该流程不用模型，全部报价为未审核草稿；上方 Harness 合成模型仍只作历史探针，不作为正式 Agent 验收依据；后续正式链路见 [[M4模型与报价修订]]。当前验证见 [[2026-10-21-演示场景与报价V1]]。


## 正式模型与两轮修订增量

正式增加“模型设置→询盘理解保存V1→修改数量存V2→修改条款存V3→对比/重开”两轮路径。模型只提建议，deterministic计算与版本提交由业务服务完成；无效输出、澄清、错误商品、鉴权/超时不生成新版本，旧基线冲突不自动覆盖。此流程仍无正式审批、语言产出与平台文化检查。 细节与当前边界见 [[M4模型与报价修订]]，本轮验证见 [[2026-10-21-正式模型与两轮修订]]。


HTML全流程复核补齐运税费依赖失效、数量单位澄清、待译与来源问题任务、RFQ包装限定及迟到审批动作校验；仅为合成交互。开发规则和FLOW-01～09见 [[项目说明书]]13.5/13.6，记录见 [[2026-10-21-产品资料全流程一致性复核]]。先产出再审核，不能把仅批准报价事实当成对未来任意文本的授权。
