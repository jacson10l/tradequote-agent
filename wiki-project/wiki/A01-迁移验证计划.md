# A01-迁移验证计划

验证分四层：A 已实际运行的 typecheck、纯 Node 探针、定向账本回归（均有退出码证据）、本机整仓 vitest（46 通过/1 既有失败，如实标注）、B/C 的接口适配与组合/桌面验收（待完成）。本页只陈述事实，不冒充未运行项通过。逐谱系识别与处置见 [[A01-迁移谱系支持与拒绝矩阵]]，追加设计与拒绝位置见 [[A01-追加迁移设计]]，决策边界见 [[0029-迁移谱系统一与拒绝边界]]，对 C 首轮至七轮核验的逐项回复见 [[A对C前置验证失败修正回复]]。

## 各输入验收预期

| 输入谱系 | 验收预期 |
|---|---|
| empty | 追加九能力，user_version=0 → 8，无任何既有数据 |
| common-v1/2/3、a01b-v4 | 追加缺失能力至统一，已存在能力只补记账本不重建 |
| c-v5/6/7 | 识别为 C 谱系，追加知识/报告/其余 run 能力至统一（修复 D1/D3/D4） |
| a-v6 | 追加 c-run5/6/7 与 check-report7 至统一 |
| b-v7 | 追加 c-run5/6/7 至统一（修复 D2） |
| unified | 无操作，账本核对指纹后不动表 |
| mixed / tampered / unknown | 只读预检抛 `MIGRATION_LINEAGE_REJECTED:<lineage>`，磁盘零写入 |

## 失败注入点（含 C 首轮核验 N07～N11）

- 缺不可变触发器/索引/列（tampered 部分能力）→ 拒绝。
- 列被改名（N07：agent_run.request_hash 改名）→ 必要列缺失判 tampered 拒绝。
- 触发器退化为空（N08：同名触发器体改为 `SELECT 1`，无 RAISE）→ 判 tampered 拒绝。
- 索引退化为非唯一（N09：同名索引去掉 UNIQUE）→ 判 tampered 拒绝。
- 触发器含 RAISE 但 WHEN 谓词永假（M13-X01：`WHEN 0` 永不触发）→ 判 tampered 拒绝。
- 部分索引 WHERE 谓词永假（M13-X02：`WHERE 0` 不索引任何行）→ 判 tampered 拒绝。
- 删除外键（M13-X03：agent_tool_step 删 run_id 参照）→ 判 tampered 拒绝。
- 删除 CHECK（M13-X04：agent_write_call 删 attempt>0）→ 判 tampered 拒绝。
- 触发器 WHEN 为比较永假（M13-X05：`WHEN 1=0`，非字面量 0）→ 判 tampered 拒绝。
- 部分索引 WHERE 为比较永假（M13-X06：`WHERE 1=0`）→ 判 tampered 拒绝。
- 唯一索引增列/改谓词（M13-X07：`agent_write_once` 多含 tool_call_id 列、`WHERE status='prepared'`）→ 判 tampered 拒绝。
- 触发器事件篡改（M13-X08：`no_delete` 改为 `BEFORE UPDATE` 仍含 RAISE）→ 判 tampered 拒绝。
- CHECK 仅在 SQL 注释（M13-X09：`/* CHECK(attempt>0) */` 无真实约束）→ 判 tampered 拒绝。
- 触发器体为字符串字面量（M13-X10：`SELECT 'RAISE';` 非真实 RAISE 调用，`stripTrivia` 清空字符串后不命中 `RAISE\s*\(`）→ 判 tampered 拒绝。
- 索引谓词字符串字面量大小写被误归一（M13-X11：`status IN ('PREPARED','COMMITTED')` 不得因转小写而误认作规范 `'prepared','committed'`，`normalizeSql` 只小写字符串外内容）→ 判 tampered 拒绝。
- 触发器体为 CASE 包裹的不可达 RAISE（M13-Y01：`SELECT CASE WHEN 0 THEN RAISE(ABORT,'…') ELSE 1 END`，`/\bSELECT\s+RAISE\s*\(/` 不命中 `SELECT CASE` 前缀）→ 判 tampered 拒绝。
- 触发器挂错表（M13-Y02：同名 `agent_tool_step_no_delete` 的 `BEFORE DELETE` 挂到 agent_run，`triggerTable.get(name)!==table`）→ 判 tampered 拒绝。
- 索引建在旁表（M13-Y03：同名 `agent_write_once` 建在 synthetic_index_target 而非 agent_write_call，`indexTable.get(name)!==table`）→ 判 tampered 拒绝。
- 旧账本未知登记（M09-L01：`schema_migration` 出现 version=99，映射之外）→ 判 tampered 拒绝，不再忽略。
- 旧账本重复登记（M09-L02：无唯一约束 `schema_migration` 重复插入同一 version）→ 判 tampered 拒绝，不再静默去重。
- 触发器体为 `SELECT RAISE(ABORT,...) WHERE 0`（M13-Y04a：RAISE 永不执行，`hasBareAbortRaise` 拒绝尾随 WHERE）→ 判 tampered 拒绝。
- 触发器体为 `SELECT RAISE(ABORT,...) LIMIT 0`（M13-Y04b：RAISE 永不执行，`hasBareAbortRaise` 拒绝尾随 LIMIT）→ 判 tampered 拒绝。
- 触发器 `UPDATE OF <不存在列>`（M13-Y05：更新其他列不触发保护，`event==="UPDATE"` 时拒绝 `UPDATE OF`）→ 判 tampered 拒绝。
- 触发器改 AFTER 时机或 `RAISE(IGNORE)`（M13-Y06：时机非 BEFORE / 动作不中止）→ 判 tampered 拒绝。
- 注释伪造保护体（M13-Y07：`no_delete` 真实体 `SELECT 1`、前置注释含 `BEGIN SELECT RAISE(...) END`，`stripComments` 剥离注释后按真实体判定）→ 判 tampered 拒绝。
- 注释分隔 UPDATE OF（M13-Y08：`BEFORE UPDATE /* gap */ OF 不存在列`，`stripComments` 补空格后 `UPDATE OF` 命中即拒）→ 判 tampered 拒绝。
- 注释伪造事件（M13-Y09：`no_delete` 真实事件 `BEFORE UPDATE`、前置注释 `/* BEFORE DELETE */`，`stripComments` 剥离后按真实事件判定）→ 判 tampered 拒绝。
- 新账本 `migration_registry` 某行 hash 被改（N10）→ 读写真开前只读拒绝，不产生 -wal/-shm。
- 新账本登记的能力在当前 schema 中不存在（N10 一致性）→ 拒绝。
- 旧 `schema_migration` 声称已执行某能力但 schema 实缺该能力（N11：c-v7 库却记 knowledge:6）→ 拒绝。
- 混合谱系（同时 c-run 与知识/报告但非 unified 精确集）→ 拒绝。
- user_version 与谱系不符（含「未知 v6」）→ 拒绝。
- 旧 B `schema_migration` 某行 hash 与已知能力指纹不符 → tampered 拒绝。
- 追加过程中坏 SQL（如 `...; INVALID SQL;`）→ 整体回滚，user_version 不变、不建半表。
- 账本已存在但指纹被改 → tampered 拒绝，不静默改写。

## 事务/回滚/重开要求

- 单 `.immediate()` 事务，识别在事务外只读完成；失败整体回滚，不部分建表、不伪记已执行。
- 重开：升级幂等追加，重试从原谱系续追，不产生半成品；拒绝重开同样只在只读预检拦截。
