# TradeQuote MVP 人工验收操作手册

本手册用于在 macOS 上启动当前集成版本，并由业务验收者实际走通商品资料导入、报价版本、重开、待确认事项和客户回复草稿。它说明当前可操作范围，不代表真实供应商资料、商业条款、认证、规则或交易已获签认。

## 1. 验收目标

确认同一报价任务可以从已发布商品资料生成报价，确定性重算阶梯价格，保留版本与检查证据，重开后继续查看，并生成供人工核对的客户回复草稿。验收时重点检查：

- 商品、单位、币种、数量档位和来源行与导入 CSV 一致。
- 商品合计与确定性计算预期一致；运费、税费和其他未提供费用保持未知或明确不包含，不得按 0 处理。
- 付款、交期等未确认条款继续显示在待确认事项中；新版本不会把旧版本覆盖。
- 客户正文不包含内部 UUID、SHA-256、内部检查标识或内部占位文字；回复明确是未经审核的草稿。
- 应用重开后，工作区、报价版本和已保存报告仍可读取；重开本身不应再次触发模型调用。

验收结果应逐项记录为“通过 / 失败 / 未执行”，附实际观察和版本信息。自动化测试通过不等于人工业务签认通过。

## 2. 验收前准备

### 设备与版本

- 本轮支持的验收环境是 macOS；Windows、签名安装包和跨平台视觉尚未验收。
- 项目要求 Node.js `22.22.0` 与 pnpm `10.13.1`。
- 使用集成分支 `codex/m1-abc-integration` 的验收版本。开始前在仓库目录运行 `git rev-parse --short HEAD` 并记录提交 SHA；不得在未确认的旧开发窗口或其他分支上验收。
- 有仓库的开发/验收人员可运行 `pnpm install --frozen-lockfile` 安装依赖。首次安装会准备 Electron 原生 SQLite 依赖，等待命令完成后再启动。

### 建议准备的资料

- 主验收目录：`docs/roadshow/c07/catalog.csv`。它是 13 行数据、4 个 SKU 的 UTF-8 CSV 小目录，包含 300/500 件 T 恤阶梯，以及 Polo、板材和紧固件样本。
- 演示询盘：`docs/roadshow/c07/inquiry.md`。内容是编写的业务案例，不是真实客户邮件。
- 业务与来源边界：`docs/roadshow/c07/source-notes.md`、`docs/roadshow/c07/README.md`。
- 500 件回复参考稿：`docs/roadshow/c07/customer-reply.md`。这是人工核对参考，不是本次运行结果，也不可直接作为供应商承诺。

不要改 CSV 来迎合预期金额，不要把另一个历史目录或过期截图当成本轮固定输入。若验收者使用自己的资料，先确认其已获授权，并记录资料版本与来源；不要将客户原件、API Key、运行数据库或未脱敏日志加入仓库。

### 数据与隐私

- 桌面端数据保存在当前用户的 Electron `userData` 本地目录。使用单独的演示/验收工作区，避免与日常业务资料混用。
- 业务文本、商品和报价片段会在模型任务时发送至已配置的 DeepSeek 服务。只有在资料使用授权明确时才启用模型；敏感客户信息请先脱敏。
- 不要为了“从空白重新演示”直接删除应用目录或数据库。需要全新数据时创建新的工作区；不要清除或覆盖验收前已有的资料。

## 3. 启动应用

在仓库根目录执行：

```sh
pnpm dev
```

Electron 桌面窗口正常打开后再操作。开发服务启动的浏览器页面不是 Electron 桌面验收，不能用浏览器预览代替本手册中的桌面行为。结束时通过应用正常退出；再次运行 `pnpm dev` 可回到同一设备上已保存的数据。

若窗口没有打开或启动命令报错：

1. 保留完整错误信息，不要清理仓库或数据库。
2. 确认 Node/pnpm 版本符合准备要求，依赖安装已经完成。
3. 记录失败命令、退出码、当前 SHA 和操作系统版本，再由工程负责人处理。

## 4. 创建本地工作区与业务场景

1. 首次启动时从侧边栏打开“工作区设置”。
2. 在“工作区名称”输入一个清楚标识为验收用途的名称，例如 `MVP人工验收-日期-验收人`，选择“创建工作区”。页面应显示本机保存状态和版本号。
3. 同页的“业务默认配置”按本次案例填写：

   | 字段 | 示例值 |
   |---|---|
   | 场景名称 | 服装询报价资料复核 |
   | 目标用户与岗位 | 外贸业务员 |
   | 目标平台 / 场景 | 客户邮件询盘 |
   | 目标市场 | 英国 |
   | 商品品类 | 服装 |
   | 目标语言 | `en` |
   | 场景来源 | 未核实配置（不可用于交易） |

4. 选择“保存业务场景”，等待“业务配置已保存”。若已有历史业务场景，确认本次变更是有意的；保存会产生新场景版本，旧报价仍保留原场景快照。

场景字段是本次演示上下文，不是已审核的平台规则，也不构成英国市场、贸易条件或商品合规结论。可按实际验收市场调整，但要记录改动。

## 5. 预览并发布商品 CSV

1. 打开“资料与报价”。在“商品与价目表”点击“选择 CSV 文件”，选择 `docs/roadshow/c07/catalog.csv`。
2. 资料名称可保留默认文件名或填写清晰名称；资料性质选“用户提供资料（人工核对）”。
3. 点击“解析并预览”。等待批次出现，检查：
   - 预览状态为尚未发布，未发布前商品不可用于报价。
   - 应有 13 个数据行、4 个 SKU；确认 T 恤 SKU `1601053415993` 的 100 件档为 `39.21 CNY`、500 件档为 `37.21 CNY`。
   - Polo SKU `1601926123092` 的混纺比例仍应显示待供应商确认，不自行补写比例。
   - 板材按 `sheet`、服装按 `piece`、币种为 `CNY`；数量档、单位、单价与文件相符。
   - 查看批次 SHA-256 和原文行信息，确认本次选择了预期文件。
4. 检查无解析问题后点击“确认发布此批次”，等待“已确认发布商品资料”。
5. 记录一项重要边界：这个按钮只将所选批次发布到当前本地工作区，允许后续报价引用；它不证明供应商、价格有效期、认证、商品真实性已经通过业务审核。
6. 点击“进入工作台处理业务”。

如预览有错误，先停止，不要发布。错误会显示原文行和字段；修正输入文件后重新预览。错误批次保留在历史中，但不能被报价选择。CSV 使用固定九列：`sku,name,category,unit,currency,min_quantity,unit_price,valid_until,description`；上限为 256 KiB、500 个数据行。

## 6. 配置 DeepSeek（模型辅助验收）

如果本轮只验收 CSV、手工报价和重开，可跳过本节。要验收询盘理解和 V2/V3 修订时：

1. 由有权限的验收者打开“模型设置”。模型服务为 DeepSeek；模型选项以当前界面为准。路演复核以 `deepseek-flash` 为既有验证配置。
2. 由验收者在密码字段输入已获授权的 API Key，选择模型，点击“保存模型设置”。不要把 Key 粘贴到询盘、终端命令、验收记录、截图或 Wiki。
3. 点击“测试已保存的连接”，等待测试结果。界面显示“连接与 JSON 测试通过”只证明连接和响应格式检查通过，不代表业务报价、商品来源或规则已核验。
4. 核对界面中的凭据状态与存储方式。设备支持系统加密时凭据加密保存；否则只保留到本次应用会话。验收完成后按团队凭据管理要求处理，不把密钥写入本地项目文件。

模型运行会发送相关询盘、商品和报价业务文本，并可能产生调用费用。每次调用都由验收者显式触发；不要为重复观察无故反复调用。运行中断而结果未知时，先检查工作台运行记录和报价版本，确认没有保存后再按界面提示显式重试。

## 7. 主流程：询盘、V1、修订与差异

### 创建 V1

1. 进入“单据工作台”，点击“新建报价任务”。确认右侧任务对话可用，先勾选“多步工具报价（读取、核价、规则校验后保存）”，用于展示真实工具调用步骤。
2. 客户名称填写验收用称呼，例如 `MVP Buyer`，不要填写真实个人信息。
3. 在“业务目标或补充说明”输入第一轮询盘（对应固定案例 `inquiry.md` 第 1 轮；可翻译，字段含义不要改变）：

   > 请根据这条询盘准备英文报价：客户要300件 SKU 1601053415993 的素色空白180gsm圆领T恤，95%棉/5%氨纶，发往英国，不加印花。请先查已发布商品资料，核对币种、数量阶梯和缺项；缺付款和交期请向我追问，不要编造。运费、税费、定制费未确定，不要算成0，也不要宣称落地总价。商品资料真实性待审核；这是编写的询盘案例，不是真实客户订单。

4. 点击“发送”，阅读右侧实际运行步骤。第一轮应先核对已发布资料并追问未提供的付款/交期信息；不要只看模型总结。若模型没有追问而直接编造条款，记录为失败。
5. 在同一报价任务中回答第二轮（对应固定案例 `inquiry.md` 第 2 轮），明确这些是拟议且尚未获供应商确认的条件：

   > 补充本次拟议条件：付款为“30% deposit; 70% before dispatch”；交期为“21 days after deposit and specification confirmation”。这两项是本次询盘的拟议条件，尚未经供应商确认，不能写成承诺。请按300件 SKU 1601053415993 保存报价版本，币种 CNY；印刷、运输、税费和其他费用未核定。贸易条件拟议为 EXW Guangzhou, China，地点仍待供应商确认。资料来自采集目录，案例为合成询盘；请保留资料待审核边界。

6. 点击“发送”并等待报价保存。左侧应出现客户报价草稿 V1；确认商品 SKU、数量、单位、币种、数量档、单价、商品金额和待确认事项。报价标题或状态应明确为草稿、未审核。
7. 重点预期值：`300 × 39.21 = 11,763.00 CNY` 商品合计。此金额不包括运费、税费及其他费用；付款、交期及 EXW 地点仍是拟议条件，不是供应商承诺。

若多步工具运行失败或未保存，不要手动编造一个运行成功的状态。记录任务记录的真实状态、错误和步骤，再依据明确失败结果决定是否重试。

### 修改为 V2

1. 确认当前选中的是刚保存的 V1，而不是其他客户/历史报价。
2. 在对话输入：

   > 将这份报价的数量从 300 piece 改为 500 piece，其他商品和已知要求保持不变。付款和交期仍未得到供应商确认；运费、税费及其他费用仍未知。请重新查询适用阶梯并核价，保存为新版本，不覆盖 V1，并报告差异。

3. 点击“发送”，等待出现 V2。确认 V1 与 V2 都能通过“选择报价与版本”访问。
4. V2 预期值：`500 × 37.21 = 18,605.00 CNY`；数量 `+200`，单价 `-2.00 CNY`，商品合计 `+6,842.00 CNY`。
5. 检查“报价版本差异”中的基准版本为 V1，逐项核对数量、阶梯、单价、商品合计和待确认事项变化。旧版不得被覆盖。

### 可选 V3 及后续修订

V3 不是本次固定 C07 主案例的必需步骤；本次验收只要求 V1→V2。**V3 不是系统允许的最高版本，也没有固定的三版上限。**如果 V3 仍不满足客户需求，选择该报价的最新版本继续修订，保存后会生成 V4；之后仍可基于最新版本继续生成 V5 等。每次成功修订只新增一个版本，旧版本保留，不会被覆盖。不要基于历史版本继续修改；界面要求先选择最新版本。

仅在验收目标明确要求验证 V1→V3 继承时执行以下可选例子：对同一合成验收案例，将 T 恤数量从 500 改为 600 `piece`，其余条件不变，并明确付款、交期和额外费用仍待确认。现有最后数量档为 500 件，预期计算为 `600 × 37.21 = 22,326.00 CNY`。必须由运行结果和报价明细确认；不得把这个数量或金额称作供应商已确认的商业报价。

确认新增 V3 后：

- V1、V2、V3 都可选择；V1/V2 数据和各自来源/检查事实未被回写。
- V3 pending 仍包含未确认付款、交期、来源/规则等适用问题；版本变化不等于确认状态变化。
- 差异基准可选 V1 或 V2，字段变化与金额重算与所选基准一致。

如果验收者不希望创造额外案例，只验证 V1→V2 即可，并将 V3 标为“未执行”；这仅表示本场验收没有执行 V3，不代表系统不支持 V3 或更高版本。不要为了填满步骤臆造真实订单变更。

## 8. 报价检查与证据

1. 在当前报价下找到对应版本的报价检查区域。首次若提示当前版本尚无报告，点击“检查并保存报告”显式运行并保存本版本报告。
2. 核对报告绑定的报价版本、场景、商品来源和检查时间。报告中的“通过”只代表当前已实现检查项的结果；没有发布的知识或平台规则不能被解释成已检查通过。
3. 展开报价“冻结的来源与计算依据”，核对 CSV 名称、原文行、数量档、单价、行金额、来源状态和有效日期。
4. 展开“任务记录”，核对实际执行的工具、澄清/失败/完成状态与保存版本。预览金额与“尚未保存”结果不能当成已经保存的报价。
5. 如一个问题显示“待核实”，不能因为报告没有阻断项就口头改成“已确认”。必要时打开“资料与报价”查询原始来源。

## 9. 客户回复草稿

1. 确认左侧选中需要验收的最新版本。
2. 展开“本版本回复草稿 · 未审核”。确认正文显示正确报价版本、数量、商品合计、币种和不含运费/税费的说明。
3. 对未确认付款或交期，客户正文应使用清晰的待确认表达，例如 `to be confirmed`，不得把“待客户确认”“来源缺失”等内部占位词原样发给客户。
4. 展开“内部核对记录”，分别检查来源、待确认项目和检查依据。内部 UUID、哈希、检查 ID 应留在内部依据，不应进入客户正文。
5. 按实际业务沟通需要核对收件人称呼、英文表达、商品描述、规格、数量、货币、贸易条件、价格有效期与适用市场。来源材料中的商品名可能是原始页面文案，应由人工判断是否适合客户阅读。
6. 点击“复制未审核草稿”只复制文本，不审批、不发送、不签署商业要约。当前人工审核/发送能力不可用；“提交人工审核”按钮处于禁用状态。

回复中的价格仍受来源审核边界约束。不要因为正文格式完整、模型语句自然或复制成功，就称报价已获供应商确认或可直接成交。

## 10. 可选：手工 V1 路径

若不启用模型，可在工作台左侧展开“手工填写报价”：

1. 填客户名称和询盘说明。
2. 选择商品行并输入数量；数量必须大于 0，且单位必须与商品资料单位相同。
3. 付款或交期未知时保持字段为空；不要输入猜测条款。
4. 点击“计算并保存报价 V1”。检查金额、pending、来源和冻结的计算依据。

此路径验证手工创建与确定性核价，不等同于模型询盘理解或 V2/V3 Agent 修订测试。

## 11. 重开与持久化验收

1. 记录现有版本数、最新版本号、商品合计、pending 项和报告状态。
2. 正常退出 TradeQuote，不清除应用数据、不删除数据库。
3. 从同一仓库再次运行 `pnpm dev`，进入同一工作区。
4. 在工作台选择同一报价的最新版本，确认报价、历史版本、pending、差异和已保存报告仍在。
5. 展开客户回复草稿及内部核对记录，确认内容仍绑定当前版本。
6. 确认打开应用没有自动触发新的模型请求；只有验收者再次点击发送才会启动任务。

如果页面暂时读取失败，按页面提供的重新加载/重试动作并记录结果。不要因短暂显示空态就创建重复报价或清空本地数据。

## 12. 可选只读缺项查询

要验证资料缺项处理，可在工作台新建查询，启用“仅查询与试算，不保存报价”，询问：

> SKU 1601926123092（195gsm Polo）的棉和涤纶比例分别是多少？只依据已发布资料回答；如果没有比例，请明确列为待供应商确认，不要猜测，也不要创建或保存报价。

确认结果说明资料没有给出混纺比例，并保留待确认状态；确认查询模式下没有新增报价版本。此查询是可选测试，不要将未查询到的资料描述为供应商已经答复。

## 13. 常见问题处理

| 现象 | 处理方式 |
|---|---|
| 工作区为空 | 到“工作区设置”创建工作区，再保存业务场景；空工作区不是程序自动加载了演示数据。 |
| 商品选择列表为空 | 到“资料与报价”检查当前批次状态；预览不等于发布，只有人工确认发布且无解析错误的商品可报价。 |
| CSV 预览报字段/行错误 | 按屏幕显示的原文行和列名修正副本，重新预览；不要用 0、1 或样品价填未知普通价格/MOQ。 |
| 提示模型未配置或连接失败 | 到“模型设置”检查保存状态并由授权人员测试连接；不要将 Key 写入询盘或终端。 |
| Agent 仍在运行 | 等待真实状态更新；不要重复点击造成第二个付费任务。 |
| 连接中断、结果未知 | 查看任务记录、报价版本和数据库返回页面；先确认是否已提交，再决定是否对同一操作显式重试。 |
| pending 项消失或回复把占位词发给客户 | 记录版本、界面文字和当前 SHA，判定本项失败；不要用手工润色掩盖系统状态问题。 |
| 报价金额与预期不一致 | 核对 SKU、数量、单位、币种、阶梯、是否选错历史版本和 CSV 行；保存证据，不手工改结果以通过验收。 |
| 复制内容与屏幕不同 | 不发送；重新选中版本、展开回复后再复制并粘贴到本地无敏感的临时文本框核对。 |
| 无法提交审核/发送 | 这是当前预期限制；按钮禁用不是可通过重试解决的故障。 |

## 15. 当前明确不在验收通过范围内

- 商品资料的真实商业有效性、供应商身份与授权、原始快照、有效期、认证真伪和人工发布审核。
- 平台规则、英国市场法律/合规判断、商务条款和供应商对付款、交期、贸易条件的确认。
- 运费、税费、定制费、落地总价、正式审批、电子签署、正式发送和 PDF 正式产出。
- Windows 运行、签名安装包、跨平台/系统缩放验收。
- 将产品用作已获供应商确认的商业报价，或将演示询盘/小目录表述为真实客户订单。

这些边界必须在演示与验收结论中保留。系统可生成供人工审核的报价草稿，不代替业务人员批准、资料发布或对外发送。
