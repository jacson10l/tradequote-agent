# 首批并行接口约定

## 状态和实施责任

B00严格schema、公共类型/端口、mock和10个客户端门禁现已纳入本次共同候选基线；C01a取消基础一并整合，见 [[分支收口与共同基线]]。新业务服务及IPC尚未接入：合法新请求仍返回CAPABILITY_UNAVAILABLE（retryable=false），非法请求返回VALIDATION_ERROR，不保存或发新IPC。旧understand/revise保持兼容。

C01b新增澄清正文/list与控制重放目标见 [[C01b存储接口与事务方案]]，待B确认交付；完整业务Wiki仍依赖 [[B00a-业务Wiki契约补充]]。当前合入代码不等于T00人类签字、正式恢复服务或知识库已完成。

第一批只接结构化知识条目（含来源/适用范围）与已有QuoteSnapshot检查，不做四格式全文抽取、任意规则代码、完整检索引擎或正式合规结论。样本可合成，sourceStatus要一路传播。未来平台/文化语言生成用独立profile版本，不能把这里两条规则样例当完整T24/T43。

## 复用的现有边界

- IPC读命令携schemaVersion=1/requestId；写命令另携idempotencyKey。actorId/origin由宿主注入，不接受模型自报。复用ErrorCodeSchema/IssueSchema，失败为ok=false/error{code,message,retryable,issues}。
- QuoteSnapshot.id是不可变revisionId；rootId??id是quoteId；version是当前版本号。V1无rootId/parentId，消费者不能漏掉V1。新版本不可借用旧CheckReport或审批。
- 金额decimal字符串、未知null；报价总额只含商品。检查服务不计算/修改金额，不允许把unknown当0。
- 模块互相只用公共导出/注入端口；domain无Electron、数据库、模型SDK；renderer只用DesktopClient。测试替身与生产结果明确分开。

## B00已实现知识与规则DTO

所有对象strict；自由文本有长度上限；空数组的业务语义必须明确测试。下列名称是本批统一命名。

| DTO | 必需字段与约束 |
|---|---|
| KnowledgeScope | platforms:string[]、markets:string[]、categories:string[]，每项1～200字，每组最多20个且不重复；空组表示该维度通用，非空与QuoteSnapshot.scenario对应字段精确匹配，三维AND；不做隐式别名映射 |
| RuleDefinition | ruleId:UUID（规则逻辑身份）、category:commercial_terms/platform_guidance、title（1～200）、message、suggestedAction（各1～2000字）、field:payment/delivery、condition以kind为判别字段的联合、failureSeverity:warning/block；第一批条件仅required和forbidden_literal，后者有1～200字literal；不接受JS/SQL/任意正则 |
| KnowledgeDraftInput | documentId:UUID、expectedVersion:非负整数（初次0）、title、scope、sourceStatus:synthetic/user_provided、sourceLabel、sourceText（1～32000字）、location:SourceLocation、rules:RuleDefinition[]（1～100条、ruleId不重复） |
| KnowledgeRevision | revisionId:UUID、documentId、version:正整数、status:staged/published、sourceHash:64位sha256、createdAt、publishedAt:时间或null、input内容快照；hash由存储端计算，不信任客户端 |
| KnowledgeQuery | scope:当前platform/market/category字符串，at:ISO时间（显式注入用于可重复测试）；返回已发布且匹配的完整revision列表及来源；不返回暂存条目 |
| KnowledgeEvidence | revisionId、ruleId、sourceHash、sourceLabel、sourceStatus、location；规则建议必须能回读此已发布版本的原文/定位 |

scope匹配依赖当前Scenario自由文本，界面提供从当前场景填入，避免手工拼写差异。sourceText范围/位置可真实回读才发布；如为text定位，start/end按JS字符串索引，摘录hash基于UTF-8，混用索引须拒绝。初次只支持text来源的结构化输入；复用SourceLocation类型不等于PDF等格式已完成。

知识状态：stage不发布、publish由human_ui触发。重复发布同revision幂等；再次编辑同document产生新version，旧已发布revision可继续按ID读取，查询只选每document最新已发布版。expectedVersion以文档所有版本最大值检查，旧基线冲突。删除/覆盖旧版本不在本批。发布是人工采用条目，不自动证明现实规则准确。

## A提供的服务/端口（契约已实现，服务待实现）

```ts
interface KnowledgeRepository {
  stage(input: KnowledgeDraftInput, context: ExecutionContext, idempotencyKey: string): KnowledgeRevisionResult;
  publish(input: { revisionId: string; sourceHash: string }, context: ExecutionContext, idempotencyKey: string): KnowledgeRevisionResult;
  findPublished(query: KnowledgeQuery): KnowledgeRevision[];
  getRevision(revisionId: string): KnowledgeRevision | null;
}
```

Repository同步方法只在业务worker内使用；公共业务service再次校验权限/schema。IPC协议为knowledge.stage/publish/query/getRevision，renderer对应具体方法，返回严格KnowledgeResult（成功data按操作判别，不能unknown），形状已由B00落实并测试，运行接线待A/C实施。query/getRevision不携幂等键，查询workspace由宿主确定，不能模型跨工作区。

成功响应统一含ok:true、warnings:Issue[]、evidenceIds:string[]。KnowledgeResult.data使用kind判别：stage/publish/getRevision返回 `{kind:"revision",revision:KnowledgeRevision}`，query返回 `{kind:"list",revisions:KnowledgeRevision[]}`；找不到单条返回NOT_FOUND而非伪造空版本。KnowledgeRevision的内容快照字段为content，类型是KnowledgeDraftInput去掉documentId/expectedVersion；documentId/version留在外层，客户端不能提交hash/发布时间/发布状态。query的at限制publishedAt不晚于查询时间，再按document选最新符合条件的已发布版本；第一批没有有效期字段，不能声称检查了法规有效期。

错误：无revision=NOT_FOUND；hash不符=SOURCE_CONFLICT；expectedVersion旧=REVISION_CONFLICT；同key异参=IDEMPOTENCY_CONFLICT；位置/字段无效=VALIDATION_ERROR；非人工发布=ACTION_NOT_ALLOWED。stage/publish与outbox/幂等同事务。新store使用现有单worker同连接，不能再开一套独立业务DB。

## B提供的检查接口/结果（契约已实现，服务待实现）

```ts
interface QuoteCheckService {
  evaluate(input: { quote: QuoteSnapshot; knowledge: KnowledgeRevision[]; reportId: string; checkedAt: string }): CheckReport;
}
```

纯函数只读快照和A返回的已发布知识，由B实现适用性复核，不直接查SQLite/模型。required判空使用trim；forbidden_literal做NFKC+toLowerCase后子串比较，不执行正则，第一批不推断词义/文化语境。field只指付款/交货事实字段，不检查客户询盘中的引用文字。A数据暂未合入时，B可用合成published fixture验证；集成验收必须切到A真实查询服务。

CheckReport字段：quoteId、revisionId、quoteVersion、checkedAt、ruleRevisionIds（排序去重）、coverage、issues。coverage按两个category列出appliedRuleIds与status:checked/pending；某类没有适用规则标pending，不能返回“全部通过”。

CheckIssue字段：checkId（同报价revision＋knowledgeRevision＋ruleId唯一、重复检查稳定，可用这些ID拼接；同修订无规则的coverage问题使用固定category键）、category、severity:warning/block/pending、fieldPath:payment/delivery或缺覆盖时scenario.platform、message、suggestedAction、evidence:KnowledgeEvidence[]。合成规则结果加sourceStatus标识/提示，不能写真实合规已通过。不匹配scope的知识不用于检查。

两种反馈共用一个CheckIssue：风险标记展示severity/数量并可点选；文本批注定位fieldPath并展示message/建议/来源。不要重新各算一套结果，不把版本差异表算作规则反馈。新报价版本重新evaluate，旧版报告保留；历史规则撤换不改写历史报告。

调用入口quote.check提交revisionId，宿主读取快照、A端口取规则后调用纯函数，返回CheckResult，不接受renderer传入伪造quote或“已通过”报告。检查只存报告，不审批/改写报价；同revision＋相同规则revision集合的结果可复用或幂等写入，checkedAt的生成规则由B00明确，重试不能刷重复报告。需要报告表时B设计，A分配后续迁移编号；第一批B可先交纯服务/双反馈组件，持久化与实际接线小PR随后合入，不宣称已经保存历史报告。

CheckResult成功data为CheckReport，错误使用公共失败结构。quote.check属于写命令（落报告），带幂等键；重试返回首次报告/checkedAt，真正新检查另用新操作键，旧报告不可覆盖。补充quote.getChecks只读命令，payload为revisionId，成功data为报告数组；报告必须有reportId:UUID以便同版本多次检查区分。pure evaluate接受显式reportId和checkedAt，生产端生成，测试显式固定，避免domain依赖系统随机/时钟。reportId在生产业务服务生成，不能作为renderer伪造报告入口。

## C提供的运行恢复接口（契约已实现，服务待实现）

保留现有agent.understand/revise输入和TradeResult兼容性；不要在同名方法悄悄改为“仅已排队”。新增agent.start/get/cancel/retry的独立严格协议，由B00导出AgentRun、RunCommand/Result和DesktopClient方法，C实现。已存在RunStatusSchema、RunEventSchema可复用，不能把只有类型当成事件持久化已完成。

AgentRun：runId:UUID、operationKey:UUID（业务幂等键）、command（不含credentials的AgentCommand）、status（复用RunStatusSchema）、attempt:正整数、createdAt/updatedAt、baseRevisionId:UUID|null、committedRevisionId:UUID|null、error:公开错误或null。重试使用同operationKey，模型请求次数可增加、报价提交只能一次；凭据临时取当前主进程配置，不落run表。

start接收业务method+payload（外层idempotencyKey作为operationKey），立即持久化queued并返回run，后台执行；get(runId)只查询。cancel携runId/requestId/idempotencyKey，不接受用户构造状态；提交前取消则无新版本，提交后取消必须保留committedRevisionId与完成事实，不撤销已提交报价。restart将未完成queued/running标interrupted，用户显式retry；不能自动重发收费请求。failed/interrupted允许retry，completed返回原版本；cancelled要由明确retry动作恢复，记录新attempt，不能自动恢复。所有状态转换含冲突/幂等测试。

RunResult成功data为AgentRun，失败复用公共错误。agent.start为write envelope，payload为去掉重复envelope的业务命令（method+payload），外层idempotencyKey就是operationKey；由worker重建现有AgentCommand，不能允许内外两个不同业务key。agent.get为read envelope＋payload{runId}；agent.cancel/retry为write envelope＋payload{runId}，它们的幂等键仅标识控制动作，不能替换run原operationKey。waiting_input用于明确缺事实，修改后的业务输入必须start新run/新operationKey，不允许原key改内容；原waiting_input可cancel，不能无变化retry导致重复澄清。

C的取消实现需AbortSignal穿透Provider，数据库提交临界区原子协调取消/完成。持久化运行与已有commitAgent使用同数据库事务协调，避免“版本写了run却丢了”。run存储迁移由A登记，C不得直接复制数据库连接或把Key写入command_json。

上述方法均接收对应完整read/write命令，不隐式产生请求键；每次重试由调用者复用业务键。RuntimeCommandSchema、RuntimeResultSchema、WorkerRequestSchema仍只接受已有执行路径；新类型不是worker白名单，C接入实际服务时再扩展并验证。preload只复用公共unavailableFirstBatchClient门禁，没有新增Main handler。

protocol.ts复用既有TradeResult的Failure/Issue结构（含currentAggregateVersion），没有为新模块发明另一套错误。新增DTO的标签/标题/范围项/literal最多200，说明/建议最多2000；sourceText不trim，以保留UTF-16定位，最多32000；规则1～100且身份唯一。标签/literal会trim，空维度为通用，大小写和别名不自动匹配；真正scope筛选属于A/B实现。旧公共错误文本边界保持兼容。

KnowledgeContentSchema与DraftInput共用原文范围校验，范围不能越界或截断代理对；B00仅允许text定位，未接四格式解析。revision发布状态与时间一致、发布时间不早于创建时间；sourceHash只验证sha256格式，真实UTF-8 hash/发布原文回读/事务幂等由A实现。查询at与scope筛选、每文档最新发布版仍是Repository责任，不能用schema通过代替查询测试。Repository的stage/publish返回更窄的KnowledgeRevisionResult，避免调用者收到list后猜测。

CheckCoverageSchema强制两类完整且不重复；无适用规则必须pending，并有唯一缺覆盖批注，无来源；warning/block必须有来源和payment/delivery定位。报告来源须属于ruleRevisionIds及该类appliedRuleIds；ruleRevisionIds排序去重，checkId不能重复；V1 quoteId必须等于revisionId。schema不执行规则、不生成稳定checkId、不保证hash对应原文，也不替代B01的业务适用性复核和双反馈UI测试。QuoteCheckInputSchema接受已有V1（无rootId/parentId）且保留null金额，只接受published知识。

AgentOperationSchema从已有两类AgentCommand直接选取method/payload。AgentRun校验operationKey等于command.idempotencyKey，理解任务baseRevisionId=null，修订任务baseRevisionId=command.payload.baseId，updatedAt不早于createdAt。completed必须携committedRevisionId，其他状态不得携提交ID；取消发生在提交后须保留completed状态，不能伪装cancelled。failed必须有公开错误，interrupted可有错误，其余状态error=null。这些是快照一致性约束，不是取消/恢复状态机；attempt变更、数据库原子性和失败后重试仍由C01实现。

只读mock的新方法与正式preload同样拒绝执行；mockKnowledgeRevision（synthetic）、mockCheckReport（两类pending）、mockAgentRun（明确合成queued）只是可导入测试数据，不冒充已保存结果。mock的原文hash为真实合成文本UTF-8 hash。单元测试从公共导入验证DTO，preload测试验证10个新方法均不发送IPC；旧工作区/手工V1/对话的Electron回归继续保留。
