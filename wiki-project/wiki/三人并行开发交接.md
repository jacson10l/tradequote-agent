# 三人并行开发交接

## 交接范围与共同起点

用户已明确要求整理交接、提交推送，且成员开发对应内容必须各自建立独立分支。本批为后续开发任务书，不表示A/B/C已实际领取或完成人工T00评审；A/B/C是真实团队角色，不是要求自动启动子Agent。

仓库为 https://github.com/jacson10l/tradequote-agent ，本批集成/交接分支为 `codex/m1-foundation`，远端入口 `origin/codex/m1-foundation`。本轮准备开始时本地HEAD为 b69c4e50060a54e656017c2b17c4bb04e836630e；这仅用于本次准备的验证，成员任务必须记录自己实际起点，不照抄该旧SHA。代码交接基线已推送为 58b462ee9c9d096c480d331036f51ae2bcfa87f6，远端SHA已核对，证据raw/parallel-handoff-git.json；后续交接状态补记为纯文档提交，成员从远端最新头部开分支；不把origin/main当本批起点，不声称已合并main或启用远端保护。

交接包括此前尚未提交的场景/CSV/报价V1、DeepSeek设置/受限V2V3、开发应用名称、共享反馈、紧凑布局及对应Wiki，不丢弃已有成果。最新能力依据 [[M2真实报价V1]]、[[M4模型与报价修订]]，历史验证与本次复验分开保留。

已实现：桌面/工作区、严格IPC、单worker SQLite、迁移1～3、不可变报价、幂等/冲突、手工V1、正式模型adapter及两轮草稿差异。真实DeepSeek语义、知识发布/规则检查、正式审批/语言产出/PDF、运行恢复、Windows/签名安装尚未通过。模型HTTP替身不是供应商验收；首页合成布局不是正式业务入口。

## 独立分支是开工前置条件

每位成员使用独立clone，或各自独立worktree；禁止三人共用同一工作目录切分支。禁止在main或codex/m1-foundation直接做成员功能。一个分支只承载一个任务/小切片；不共享feature分支、不强推他人分支。

新同事首次获取：

```sh
git clone https://github.com/jacson10l/tradequote-agent.git
cd tradequote-agent
git fetch origin
# A执行；B/C将分支名替换为上表对应名称
git switch --no-track -c codex/a01-knowledge-publish origin/codex/m1-foundation
git rev-parse HEAD
```

将最后输出记录到自己任务页为taskBase，记录OS/CPU/Node/pnpm和领取人。已经有仓库者先检查 `git status --short`，未提交工作先在原任务保存，不能用reset/clean清掉；已有同名任务分支就继续该分支，不覆盖重建。B00合并后，B从更新的集成分支另开B01，不能把未合入的契约隐藏在大功能PR里。

每天集成前抓取远端；已有发布分支优先merge共享分支，避免需要force push：

```sh
git fetch origin
git merge origin/codex/m1-foundation
# 完成代码、Wiki和测试后再正常提交/推送自己的分支
git push -u origin HEAD
```

PR目标为codex/m1-foundation，C汇总集成；成员不得自行把目标改main。非作者评审通过并满足本地/实际CI检查后合入；main的后续合并另行安排。当前只有仓库工作流配置，远端运行与分支保护需核实，不能口头假定强制生效。

## 环境与开工冒烟

固定Node22.22.0、pnpm10.13.1，单一pnpm锁文件。先运行 `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm check`，再 `pnpm dev` 建合成工作区，保存场景→发布合成CSV→手工100件V1商品合计900.00 USD→重开读取。每人记录自己机器的实际结果；Windows开发启动失败须先由C协助修复，不能拿macOS结果代替。

`pnpm test:e2e` 使用隔离目录/合成HTTP，验证已有完整桌面路径；不需要真实Key。真实Key只在正式“模型设置”输入，不进聊天、测试夹具、Wiki或提交。C在有权限的账户上单独执行真实模型两轮评估；缺Key写未运行，A/B仍可继续。

## 依赖与合入顺序

1. B00先实现 [[首批并行接口约定]]；A核对知识/迁移接口，C核对IPC/run；实际评审结论写B任务页。未评审不标T00全部完成。
2. A样本工作、C模型实测与取消状态机可与B00并行；需要新类型的代码在B00合入后再接入。禁止复制一份本地DTO或用any临时兼容。
3. A01与B01、C01可并行实现。B01纯检查/界面用明确合成published规则开发；真实数据联调等A01查询服务合入。C01取消恢复不依赖规则服务，不将A/B列为虚假前置依赖。
4. A先合知识存储和迁移4；C的run迁移预留5，C在自己的分支测试前先merge已落地的迁移4，或先提交无数据库依赖的状态机小PR。编号有其他任务占用时A统一重排未发布迁移，不覆盖已合并迁移。不得由两人改同一个migration条目。
5. B合检查服务/面板和持久化接口；C合桥接、worker和导航，将已完成模块接成“发布知识→检查指定报价→双反馈→修订重检”，并保留V1/V2/V3回归。三方不等到整批结束才第一次联调。

## 每个PR必须带的交付

任务ID/负责人、实际taskBase、接口变化与失败码、改动文件、演示步骤、实际验证命令/退出码、Wiki知识/任务链接、未完成项。每个作者更新自己的知识页和任务页，追加log；新增源文件同时登记coverage与导航。公共知识页只修改相关段落，避免互相覆盖整篇。

```sh
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build
pnpm wiki:generate
pnpm check
pnpm wiki:test
git fetch origin
git merge-base HEAD origin/codex/m1-foundation
# 将上条真实输出填入，不能拿刚提交后的HEAD规避本次改动
node wiki-project/scripts/check-wiki-sync.mjs . --base <实际merge-base>
git diff --check
git diff --cached --check
```

纯文档变化可以只运行生成/check/lint/sync及相关门禁；变动金额/事务/模型/桌面时必须跑对应行为测试。若无平台环境，记录未运行，并安排具备环境的成员补验。合成规则只证明引擎，不写“目标国/平台合规已通过”。三张开发任务初始均未实现；本轮完成的是交接和共同代码基线。
