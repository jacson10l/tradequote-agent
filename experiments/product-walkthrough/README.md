# TradeQuote 业务全流程交互演示

直接用现代浏览器打开 [index.html](index.html)。这是一个独立HTML：样式、脚本、合成数据全部内置，不安装依赖、不联网、不调用真实模型，不连接正式应用数据库。

它用于配合[项目说明书](../../wiki-project/wiki/项目说明书.md)解释目标业务，包含正式项目尚未交付的功能交互。界面各页的“开发说明”展示职责、对应说明书章节与正式实现边界。请勿输入真实客户资料或凭据。

## 推荐演练

1. 从“业务总览”进入预置的100件上衣报价V1，商品合计900.00 USD，费用未知。
2. 报价助手选择“数量改为120 piece”，提交生成V2，商品合计1080.00 USD；再选择“付款与交期”，提交生成V3。
3. 打开风险与批注/确认任务，处理运税费50 USD，生成V4；数量变化已使旧包装确认失效，还需在包装面板重新采购确认并填写包装已含价目的依据，再生成V5，总额1130.00 USD。查看旧V1仍为900.00 USD。
4. 审核与输出生成英语RFQ正文，提交审核，填写审核人并勾选核对项，批准此产出。下载文件不会标记发送；“模拟标记已发送”只增加本地记录。
5. 切换德语和正式邮件，再生成新产出，观察它不继承英语产出的审批。编辑正文也会新建未审核产出。
6. 商品与资料导入NEW系列CSV样本，预览后人工发布。重复SKU/数量档位和非法字段会阻止发布。
7. 业务知识库创建候选、模拟整理、保存、人工审核，再单独发布；可搜索、筛选、回读来源、修订和撤回。撤回或替换产出引用的规则会要求重新核实。
8. 设置模拟延迟8秒，在运行期间取消或刷新。取消不写新版本，刷新后中断且不自动重试；失败注入支持超时、鉴权、非法输出，显式重试与成功结果回放不重复提交。
9. 手工编辑事实可增加/删除商品行、改变数量、付款/交期/包装、费用确认、成本核价、目标毛利、折扣及固定演示汇率。历史版本只读，恢复历史会创建新版本。
10. 备份下载JSON，恢复前显示摘要并确认；重置预置样本或清空演练只影响本HTML自己的存储键。

## 模拟范围与真实边界

- 新建询盘支持页面列出的“请报价 SKU 数量 单位；付款：…；交期：…；包装：…”离线句式，预览原文片段、商品匹配、知识版本和缺项后人工确认建单。歧义、单位不匹配、重复字段和未知片段先澄清，不部分保存。多商品仍可人工建单；不宣称理解任意原文。修订仍仅识别数量/付款/交期句式。
- 商品CSV实现有界本地解析；XLSX/PDF/DOCX未在HTML中提供伪解析。CSV中的位置为逻辑记录行，不冒充复杂多行文本的物理起始行。原始销售价只接受USD，报价可用明确的固定汇率示范USD/EUR/CNY。
- 价格使用BigInt定点计算，销售单价保留四位，行金额两位HALF_UP；成本模式先将目标售价舍入至两位，再计算行金额。未知费用不当零。这里的算法只服务教学，生产规则以domain代码和领域契约为准。
- 规则检查是固定的合成合同/市场规则，只有已发布、适用、有效且原文/正文/范围与对应合成fixture匹配的知识才绑定检查；同类但不同内容的知识显示待核实。报告冻结版本、原文片段、位置、字段和检查说明；编辑知识正文不会动态生成可执行规则。知识原文与正文作为文本显示，不执行Markdown/HTML，不宣称完整业务LLM Wiki实现。
- 已知合成付款/交期/包装条款有固定英德译文，其他条款显示原文待译并阻止送审，任务入口引导补译为新产出。英语RFQ为摘要与追问，正式邮件包含商品价格表、费用、条款和确认事项；德语数字显示小数逗号且不改变事实。其他语言代码可以提交，但无离线模板时明确未支持，不生成产出。非样例平台使用通用回退并阻止正式送审。无真实翻译模型、法律合规判断或人工语言验收。
- 输出为带合成标识的TXT/HTML，PDF通过浏览器打印窗口“另存为PDF”。不是Electron printToPDF；不同浏览器的下载/弹窗/打印限制仍适用。
- localStorage保存模拟状态；被浏览器禁用时退回内存。只有一个演示工作区，没有真实权限/多用户/数据库事务。冻结快照由应用逻辑保护，不宣称浏览器存储不可篡改。
- 时间有效性统一按演示日2026-10-21判断，避免之后打开样本全部失效；操作时间仍记录实际本机时间。

## 本轮新增演练：从原文到依据

1. 点击“新建询盘”→“需要澄清的询盘”→识别。应显示候选SKU、缺数量/单位与未识别片段，不能建单。
2. 返回补充，选择“有缺项的上衣询盘”。逐项查看原文字符位置、商品价目来源、合同/市场/术语发布版本与原文；勾选确认后模拟保存V1。包装与运税费应仍待确认。
3. 在“依据与来源”回读建单识别记录；之后修改数量，建单证据仍保留100，当前报价/差异显示120，不把原文证据改成新事实。
4. 默认市场改法国，再修改这张德国报价的数量或恢复历史：新版本仍是德国。另建新单才使用法国；法国缺少已绑定的市场依据时不放行审核。
5. 在知识库为市场知识新建修订，把正文改成“无需包装”，审核再发布。报价检查应显示“市场依据缺失或尚未绑定检查”；旧报告/引用可回读，不能仅凭同类知识判通过。
6. 在审核与输出生成英语RFQ和德语正式邮件：比较摘要/追问与四段详细内容；德语金额如USD 1.080,00。选择其他语言，输入fr/ja/ar，明确提示没有模板，不新增产出、不继承审批。

新建报价不默认包装；只有预置的100件演示单显式携带合成包装。旧缓存、旧报价和旧产出不改写。新增识别证据、报告依据、语言请求与场景模板标记是可选演示字段，继续使用原localStorage键/schema；旧版待执行“模拟理解”因无原文证据要求重新发起。直接双击仍是目标用法，本轮实际浏览器验证使用localhost HTTP。

## 按详细规格核对

对应[说明书](../../wiki-project/wiki/项目说明书.md)第5.5、7.4、8.3、9.4节；逐项用例位于13.4节。

- 新建询盘选“跨品类板材询盘”，检查原文片段、DEMO-PANEL/12.5 m2及来源，确认后商品合计225.00 USD，费用仍未知。选“需要澄清的询盘”应先出现问题，不建立报价。
- 人工新建板材且不填包装，应待确认；预置上衣的标准纸箱仅是样本事实。包装面板分别展示买家要求/待核实、待接受建议、已接受待采购、已确认/不适用，所有确认只用于合成演示。
- 德国报价建好后，把工作区默认市场改为法国，再修改旧单数量；旧单新版本仍为德国，新建单才用法国。更换已有报价请使用单据顶部“更换本单市场”，填写原因、预览影响后确认；不使用设置页冒充改单。
- 知识原文/正文改成不匹配的同类文本，发布后检查应待核实；旧报告冻结证据不变。
- 同一版本生成RFQ摘要及正式邮件，比较结构和金额；输入fr/ja/ar等语言应明确未支持且不伪生成。其他平台显示通用回退，不冒充已完成平台适配。

完整多来源检索、独立澄清答案历史、正式包装服务、任意语言模型与人工文化复核是正式产品剩余要求；以说明书规格实现，不能照搬样机限制。

## 新增交互演练：市场与包装

1. 打开单据“查找包装建议”：显示已发布合成资料、段落、SKU/市场范围；新版本状态为待接受。无匹配资料时不编造建议。
2. 接受建议后仍为待采购确认；也可拒绝并说明原因，保留原买家要求。采购人工确认需填写确认人、适用性证据及费用处理。
3. 费用选择“另计包装费”输入12.345 USD，保存后显示12.35 USD；“已含”或“明确零”必须填依据，“费用待确认”继续阻止总额定稿。运税费不得重复计入另计包装费。
4. “更换本单市场”把德国改法国，填写原因并预览，勾选确认后新建版本。差异显示市场和包装确认/费用失效，法国无合成规则显示待核实；工作区默认及旧版本不变。
5. 修改数量或包装文字，原采购确认不再适用；恢复历史也新建版本并重新确认。旧缓存没有包装确认记录会显示待核实，可直接补确认，无需重置历史数据。

包装与市场交互使用同一报价版本链。已批准旧产出保留历史，新版本和新产出须重新审核；这些演示没有真实供应商/权限/法规校验。


## 全流程检查后的开发用法

可以用本HTML与项目说明书建立共同产品认知、拆分模块和编写验收；正式DTO、金额规范、数据库事务、Agent工具和权限必须按契约/源码实现，详见说明书13.6。八页均有合成操作，但多格式、任意语言、通用规则执行、真实采购、持久化恢复和正式PDF仍需正式开发。

补充演练：

1. 运税费已确认后修改数量、币种、定价、包装或交期，费用转待核实，旧版不变；采购按新上下文重新确认。只改付款不影响费用。编辑表单重新确认框不会预勾选。
2. 板材m2报价输入“付款改为30%；数量改为120件”，整次澄清且无部分保存；改用120 m2（或省略单位）才接受。
3. 自定义付款“需要专用信用证条款”，生成英语正文后查看待译阻断与任务→处理产出问题→编辑补译→新产出→送审/驳回/再送审。手工编辑须逐项对照报价，不因删除标记而宣称自动验证事实。
4. 撤回产出引用的术语/规则，审核页显示原因，任务页可定位；历史批准仍保留但不能下载已审核版本或记录发送。恢复有效依据后重新生成再审批。
5. RFQ和邮件都能看到未确认的包装要求及限定；历史报价的当前重检与历史检查报告分开阅读。发送/驳回弹窗的迟到确认会重新验证基线。

验证范围与命令记录见[全流程复核任务](../../wiki-project/wiki/tasks/2026-10-21-产品资料全流程一致性复核.md)。
